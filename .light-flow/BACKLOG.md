## Диалоги: проверено по документации (ресёрч для фазы 03)

- [ ] `closedby` ставить **явно всегда**. Если атрибут не задан или невалиден,
      то для диалога, открытого через `showModal()`, поведение = `closerequest`,
      то есть **Esc закрывает**. Для остальных случаев = `none`.
- [ ] Поддержка `closedby`: Chrome 134, Firefox 141, Safari — preview. Нельзя
      делать его единственной защитой от закрытия, нужен второй барьер —
      перехват `cancel` через `preventDefault()` (как в исходнике, `tic-menu.js:121`).
- [ ] `showModal()` блокирует вне диалога **всё**: клики, фокус, любые
      взаимодействия; Esc закрывает только последний показанный модальный диалог.
      Отдельная обработка pointer-events не нужна — браузер делает это сам.
- [ ] Для действий, которые можно отменить (подтверждение выхода), использовать
      `requestClose()`, а не `close()`: он сначала стреляет `cancel`, где закрытие
      ещё отменяемо. `close()` закрывает немедленно.
- [ ] Invoker Commands API: `<button command="show-modal" commandfor="id">`
      открывает диалог без JS. Заложить в универсальный компонент кнопки.
- [ ] Анимация диалога нативно: `@starting-style` + `transition-behavior:
      allow-discrete` + `display` и `overlay` в списке `transition`. Без `overlay`
      элемент исчезнет из верхнего слоя мгновенно. У `::backdrop` закрытие
      не анимируется — он удаляется сразу.
- [ ] Не ставить `tabindex` на `<dialog>` — запрещено. Ставить `autofocus` на
      элемент, с которым пользователь взаимодействует сразу.
- [ ] Подтверждения через `formmethod="dialog"`: кнопка с `value` закрывает
      диалог и кладёт значение в `returnValue`.

## Дизайн и вёрстка

- [x] **Решение по библиотекам для фазы 04** — **закрыто в фазе 04**:
      иконки — `@lucide/vue` (ISC) через реестр «токен → компонент» с явными
      импортами; компонентные и CSS-библиотеки не брались. Обоснование и цены —
      в PLAN/REPORT фазы 04.
      - **Иконки — брать.** В метаданных формы `icon` остаётся нейтральным
        строковым токеном (иначе Vue протечёт в ядро), а библиотека
        подключается как реестр в UI: токен → компонент, по образцу реестра
        контроллов по `kind`. Кандидаты: импорт по иконке (например
        `lucide-vue-next`) или сборка во время билда (`unplugin-icons`).
        **Версии, лицензии и размер проверить ресёрчем фазы 04**, по памяти
        не утверждать.
      - **Компоненты — не брать.** Диалог, формы и схлопывание уже написаны на
        нативных `<dialog>` и `<details>` с реестром; библиотека их
        продублировала бы. Вернуться, когда появится конкретный сложный виджет
        (список с поиском, виртуализация, drag-and-drop) — тогда headless-
        библиотека под этот виджет, а не «компоненты вообще».
      - **Стили — не брать.** Своя система темы (токены, OKLCH, системный
        акцент, `light-dark`, `color-mix`) уже работает; CSS-фреймворк занял бы
        её место и принёс preflight, конфликтующий с `base.css`. Фаза 04
        проектирует язык оформления, а не принимает чужой.
      - **Подглядывать в чужие решения — можно и нужно.** Из библиотек стоит
        подсматривать API, приёмы и структуру (как устроены реестры, хендлы,
        a11y-детали), чтобы не изобретать велосипед. Нельзя — подключать их в
        проект: это уже другой выбор, с ценой в зависимостях.
- [ ] **В роадмапе нет фазы на вёрстку и визуальный дизайн** — **закрыто**:
      дизайн стал фазой 04 (решение D11/D12 фазы 03). Композиция, отступы,
      сетка, адаптивность и внешний вид компонентов проектируются там.
