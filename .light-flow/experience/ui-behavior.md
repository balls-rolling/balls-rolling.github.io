# Опыт: поведение UI

Уроки спринта 02 (бильярд), фаза 04-c. Каждый урок оплачен найденным дефектом.

1. **Новый вариант элемента → аудит глобальных селекторов.** `input` в
   `src/styles/base.css:55-61,83-93` накрыл `input[type="range"]`: слайдер силы
   получил `cursor: text`, `user-select: text`, фон/рамку/паддинги текстового
   поля. Исключения были только для checkbox/radio. Правило: добавляя вариант
   элемента, grep'ать глобальные селекторы, под которые он попадает.
   **Спринт 03 (02-c): вылечено в источнике** — range исключён из общих правил
   (`input:not([type="range"])`) и получил свой вид (`appearance:none` + трек и
   бегунок); точечных исключений на месте не плодим.
2. **Меняющиеся числа → `tabular-nums` + место под максимум.** Подпись «N%»
   (`BilliardsUi.vue:279-282`, `min-width: 3.5ch` без tabular-nums) прыгала
   30.19 → 38.97px, панель росла 412.98 → 421.61px на «100%». Крайние значения
   (0/100) проверяются первыми — это первое, что смотрят у контролла.
3. **Нативный `range` в боксе текстового поля ломает геометрию.** `appearance:
   auto` + `box-sizing: border-box` + `padding: 8px 12px` + `border: 1px` при
   width 220 дали content-box 194px: бегунок физически не доходит до края.
   Стилизация range — решённая задача (`appearance: none` + свой thumb), не
   изобретать.
4. **Отладке не место в прод-UI.** `revision {{ snapshot.revision }}`
   (`SessionHost.vue:48`) виден игроку. Отладочное — в тестовую игру/HUD, не в
   игровой слой.
5. **Две точки перевода координат без общего хелпера расходятся молча.**
   `angleFromEvent` считает fit от `getBoundingClientRect`
   (`BilliardsUi.vue:62`), рендер — от `frame.size` (`render.ts:118`). Пока
   совпадают; при CSS-повороте (D4) разойдутся. Общий хелпер до фазы ориентации.
6. **Состояние только-для-вида — в рантайм-слот, влияющее на ход — в `Move`.**
   Прицел и поставленный биток живут несериализуемыми рантайм-слотами (как
   `#aim`), чтобы не пачкать `BilliardsState`/сохранения; но позиция битка
   влияет на результат — поэтому она входит в ход (`{angle, power, cueY}`),
   иначе сериализация/сеть не воспроизведут удар (спринт 03, 02-b).
7. **Все ветки рендера получают один и тот же набор параметров вида.**
   Ранний `return` в `BilliardsGame.draw` для реплея передавал опции без
   `bottomInset` — на время анимации стол вписывался крупнее, и панель его
   перекрывала; после покоя скачок возвращался (спринт 03, 02-c). Наблюдаемый
   «дёргается только во время удара» — почти всегда разница параметров между
   ветками рендера.
