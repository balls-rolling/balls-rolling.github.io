## Отклонения от плана

1. **`tsconfig.node.json` пришлось изменить дважды.** Первая версия указывала
   `types: ["node"]`, но `@types/node` в зависимостях нет. Вторая версия не
   компилировалась: `vue-tsc` требует у referenced-проекта `composite: true`
   и запрещает `noEmit` (ошибки TS6306/TS6310). Итог: `composite: true`,
   `emitDeclarationOnly: true`, `outDir` в `node_modules/.tmp`. Node-типы
   не понадобились — `vite.config.ts` их не использует.
2. **`baseUrl` убран из `tsconfig.json`.** TypeScript 6.0.3 объявляет опцию
   устаревшей и требует `ignoreDeprecations: "6.0"`, иначе ошибка TS5101.
   Алиас `@/*` в TS 6 работает и без `baseUrl`, поэтому опция удалена целиком
   вместо глушения предупреждения.
3. **T5 выполнена раньше планового порядка.** `src/main.ts` импортирует
   `@/core/theme`, поэтому палитра должна была существовать к моменту проверки
   T2. Создана в порядке T2 → T5 → T4; логика и содержание не изменились.
4. **`RegistryPanel.vue` создан вместе с T7**, а не отдельной задачей: без него
   работа реестра не наблюдаема в браузере, а тестового раннера в фазе нет.
5. **Совпадения слов в grep** при проверке «ядро не знает игр» дают ложные
   срабатывания на `probe` — имя скрытого DOM-элемента для чтения `AccentColor`
   (портировано из `palette.js:7`). Проверка выполнена вручную, вывод интерпретирован.

## Правки по итогам verify

Найдено при верификации, исправлено по команде пользователя.

1. **`pointer-events: none` стоял на всех трёх слоях без достаточного основания**
   (`ui/shell/layers.css:15`). Клик по прозрачной области проходил сквозь все
   слои сразу, а условие T6.2 обещало перехват верхним слоем. Разложено по
   назначению:
   - слой 1 (игровое поле) — `auto`, это поверхность ввода;
   - слой 2 (игровой UI) — `none` на контейнере, `auto` на прямых детях,
     иначе полноэкранный слой закрыл бы поле, но контролы внутри работают;
   - слой 3 (диалоги) — `none`, иначе пустой полноэкранный контейнер закрыл бы
     всё поле; блокировку под собой обеспечивает сам модальный `<dialog>` —
     `showModal()` выносит его в верхний слой браузера и делает всё вне него
     inert, z-index не участвует;
   - метка слоя — `none`, диагностическая и ничего не перехватывает.
2. **Запрет контекстного меню не был перенесён.** Живёт в исходнике в JS
   (`js/app.js:15-18`), а не в CSS, и пропущен при переносе `global.css`.
   Добавлено в `src/main.ts`: блокируется везде, кроме полей ввода, где нужен
   paste (в фазе 09 туда вставляются коды приглашений).

Проверено после правок: `vue-tsc` код 0, сборка код 0, слои 2 и 3 не
перехватывают клик (клик в центре доходит до слоя 1), `registry-panel` внутри
слоя 2 остаётся интерактивным, контекстное меню заблокировано на странице и
разрешено в полях ввода.

3. **Ресёрч по диалогам по требованию пользователя.** Проверено по MDN и
   официальным данным поддержки (BCD). Результаты перенесены в `PROJECT.md`
   как правила и в `BACKLOG.md` как задачи фазы 03; здесь фиксирую главное,
   что влияет на уже сделанное:
   - `showModal()` блокирует вне диалога **всё** — клики, фокус, любые
     взаимодействия. Ручная блокировка не нужна, `z-index` не участвует.
     Это подтверждает решение по `pointer-events` на слое 3.
   - **`closedby` при отсутствии атрибута для `showModal()` даёт `closerequest`,
     то есть Esc закрывает диалог.** Атрибут обязан ставиться явно.
   - Поддержка `closedby`: Chrome 134, Firefox 141, Safari — preview. Нужен
     второй барьер (перехват `cancel`), как и сделано в исходнике.
   - `requestClose()` вместо `close()` для отменяемых закрытий.
   - Есть Invoker Commands API — декларативное открытие/закрытие диалогов,
     годное для универсальной кнопки в `ui/`.
