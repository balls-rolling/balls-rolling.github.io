# CONTEXT — Фаза 04: Дизайн и вёрстка

## Что делает фаза

Приводит уже работающий UI фазы 03 к единому, современному и адаптивному виду.
Меняется **только внешний вид**: поведение, навигация и структура экранов
остаются прежними. Единственное функциональное исключение — переключатель темы
(D4).

**Готово** — значит: путь «меню → список игр → преднастройка → сессия», лобби и
настройки выглядят аккуратно и адаптивно; светлая/тёмная тема и системный акцент
сохранены; компоненты (диалог, формы, кнопки, поля, группы) оформлены
единообразно; на малом окне содержимое не ломается.

## Принятые решения

### D1. Строгий объём: только внешний вид

Поведение не меняется — это прямое требование роадмапа. Пересмотр навигации меню
(«минимизировать действия», бэклог) в фазу **не берётся**: это UX-задача, а не
оформление, и она потянула бы за собой поведение. Оставляем отдельным будущим
решением.

### D2. Визуальный язык: база источника + современные гайды

Основой берём палитру и токены источника (`--bg-*`, `--card`, `--fg`, `--line`,
`--accent`, `--radius*`, `--shadow`), уже перенесённые в `styles/tokens.css`, и
доводим их до современного уровня, опираясь на публичные дизайн-гайды крупных
платформ (Apple HIG, Google Material, Microsoft Fluent — конкретные ориентиры
уточняются ресёрчем на plan). Сохраняем проверенное решение источника: главное
действие — градиент через `color-mix(in oklch, …)` с фиксированным тёмным текстом,
чтобы контраст держался в обеих темах.

### D3. Композиция: центрированная карточка, один столбец

Диалог — центрированная карточка с ограничением по ширине (`max-width`), экраны —
вертикальный поток в один столбец. На малом окне — внутренний скролл содержимого,
а не сжатие в нечитаемое. Адаптивность по ширине и высоте (`dvh`, безопасные
зоны), плотность средняя. Сетки и две колонки не вводим — контента для них нет.

### D4. Переключатель темы (единственное функциональное исключение)

Тема сейчас берётся только из ОС (`prefers-color-scheme`). Добавляем ручной выбор
**Системная / Светлая / Тёмная**, по умолчанию — «Системная». Значение хранится в
глобальных настройках (localStorage, рядом с именем), переживает перезагрузку;
палитра реагирует на ручной режим. Место в UI — экран настроек. Это осознанное
исключение из «только внешний вид», согласованное с пользователем.

### D5. Общие UI-примитивы

Оформление выносим в небольшой набор общих примитивов (кнопка, поле, группа и
т.п.) и переиспользуем их, а не дублируем стили по компонентам. Это соответствует
минимализму и убирает расхождения между экранами. Реестры контроллов по `kind` и
экранов остаются как есть — примитивы меняют только их вид.

### D6. Иконки: интерфейс объявлен, выбор — ресёрчем на plan

`Control.icon` остаётся строковым токеном в ядре (Vue в ядро не протекает).
Реальная библиотека подключается в UI реестром «токен → компонент» (по образцу
реестра контроллов). Конкретный выбор (`lucide-vue-next`, `unplugin-icons` или
иной) и его версии/лицензия/размер **не фиксируются сейчас** — решаются ресёрчем
на стадии plan, по памяти не утверждать.

### D7. Библиотеки компонентов и стилей не берём

Диалог, формы и схлопывание уже написаны на нативных `<dialog>`/`<details>` с
реестром; компонентная библиотека продублировала бы их. CSS-фреймворк занял бы
место собственной системы токенов и принёс preflight, конфликтующий с `base.css`.
В чужие решения подсматриваем, но не подключаем.

## Отклонённые варианты

| Вариант | Почему отклонён |
| --- | --- |
| Включить пересмотр навигации меню | Это UX/поведение, противоречит «только вид» (D1) |
| Проектировать токены с нуля | Проверенная база источника уже есть; выгоды нет (D2) |
| Сетки и две колонки | Контента для них нет, усложняет (D3) |
| Оставить тему только из ОС | Пользователь выбрал ручной переключатель (D4) |
| Локальные стили в каждом компоненте | Дублирование и расхождения (D5) |
| Компонентная/CSS-библиотека | Дублирует нативное, ломает токены (D7) |

## Объём фазы

**Делаем:** доводку токенов и типографики; общие UI-примитивы; вёрстку существующих
экранов и компонентов формы; композицию центрированной карточки со скроллом;
адаптивность по ширине/высоте; переключатель темы; ресёрч и подключение иконок
(если ресёрч подтвердит).

**Не делаем:** изменение поведения и навигации; фоновое демо (фаза 05); игровое
поле и Viewport (фаза 06+); игровой UI (фаза 08); сеть (фаза 10).

## Открытые вопросы

- **Конкретные гайды** (Apple HIG / Material / Fluent или их сочетание) — какие
  берём за ориентир; уточняется ресёрчем на plan.
- **Иконочная библиотека** — выбор и обоснование (версии, лицензия, размер,
  tree-shaking); решается ресёрчем на plan.
- **Форма настроек темы** — сегментированный контрол, список или радиогруппа;
  деталь уровня plan.
