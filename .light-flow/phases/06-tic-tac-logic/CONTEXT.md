# CONTEXT — Фаза 06: логика крестиков-ноликов + ИИ

## Что делает фаза

Переносит из эталона `C:\projects\light-flow\tic-tac` **чистую логику** игры на
TS: движок правил (победа 5+ в ряд на бесконечном поле), мозг ИИ (эвристика,
уровни, ошибки) и математику сложности (рейтинг 0..100), плюс адаптер игры над
базовым `Game`. Всё тестируется без DOM и без рендера.

**Готово** — значит: правила, ИИ и сложность покрыты тестами на vitest, зелёными;
логика и ИИ работают без рендера; адаптер `TicTacToeGame` играет партию через
`Game`-контракт (ходы, победа, очередь).

## Принятые решения

### D1. Правила — порт 1:1

`rules.ts`: `key(x, y)`, `canPlace(sets, x, y)`, `findWin(set, x, y)`,
`WIN_LENGTH = 5`, 4 направления. Победа — **5 и более подряд** от последнего хода;
поле бесконечное, ничьей нет. Перенос из `rules/engine.js:1-64` без переосмысления.

Обоснование: источник well-factored и проверен (`PROJECT.md:105,121`), это прямо
заявленный объём. Отклонено: переписывать правила «чище» — риск регрессий без
выгоды.

### D2. Мозг ИИ — порт 1:1

`brain.ts`: `candidates(own, opp)` (радиус 2), `scoreCell`, `chooseMove(own, opp,
level, opts)`, `ERROR_BY_LEVEL = [1, 0.25, 0.15, 0.08, 0.05]`, `opts.missWin`
(пропуск победы — для демо ИИ vs ИИ). Перенос `ai/brain.js:1-87`.

Обоснование: проверенная эвристика; демо-режим источника опирается на `missWin`
(`PROJECT.md:122-123`). Отклонено: заменять ИИ (нет причины, фаза про перенос).

### D3. Сложность — чистая математика, персистентность позже

`difficulty.ts`: `levelFor(rating)` = `floor(rating/25)` в 0..4; `applyResult`
(победа растит на `min(15,max(3,15-moves/2))`, поражение −8, кламп 0..100) как
**чистые функции над состоянием рейтинга**, без `localStorage`. Перенос математики
`ai/difficulty.js:35-52`.

Обоснование: рейтинг — **игровое свойство игрока** (BACKLOG: «Рейтинг сложности ИИ
как свойство игрока»), платформенное хранилище и ключ `game/<id>` (D6 фазы 02)
подключатся на экране настроек игры (фаза 07); чистая математика тестируется в
node. Отклонено: тянуть `localStorage`/фолбэк в память (дубль проблемы
`settings.js:6`/`difficulty.js:5`, BACKLOG:60-61).

### D4. Адаптер `TicTacToeGame extends Game` — только логика

`TicTacToeGame` реализует контракт `Game` (`src/core/game/game.ts`): начальное
состояние (наборы камней по игрокам + глифы X/O), `applyMove` (проверка клетки,
победа через `findWin`), `chooseMove` (мозг ИИ против камней соперника),
`nextPlayer` (по очереди), `isFinished`. Уровень ИИ и `missWin` — настраиваемые
поля экземпляра (для тестов и демо), задаются позже формой преднастройки (фаза 07).

Обоснование: контракт ядра уже есть (`game.ts:12-37`), адаптер делает логику
проверяемой через `Game`, а `GameEnvironment` и `Session` не меняются (принцип
7a). Настраиваемый уровень — потому что `chooseMove(state, playerId)` не видит
`Player`, и сложность должна жить в игре. Отклонено: добавлять уровень в ядро
`Session` (протечка игровой специфики).

### D5. Тесты — vitest, порт источника

`rules.test.ts`, `brain.test.ts`, `difficulty.test.ts`, `game.test.ts`. Порт
проверок `test/rules.test.js` и `test/ai.test.js` плюс проверки адаптера (победа
через `applyMove`, чередование, отказ на занятой клетке). Нестабильность
`Math.random` обрабатывается как в источнике: тесты проверяют вынужденные ходы
(победа/блок) и `missWin`, а не точный ход.

Обоснование: источник уже содержит эти тесты (`PROJECT.md:117`), в проекте есть
vitest с окружением node (D4 фазы 02).

### D6. Без рендера, UI, реестра и настроек

В этой фазе нет `index.ts`-записи реестра, формы преднастройки, рендера на
Viewport, Vue-компонентов и записи рейтинга. Логика вызывается только тестами.

Обоснование: ROADMAP 06 — «логика и ИИ работают без рендера»; рендер, UI и
`Game.render` — фаза 07. Отклонено: добавлять `Game.render` (задел 07 оставлен
чистым).
