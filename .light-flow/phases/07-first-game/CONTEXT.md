# CONTEXT — Фаза 07: первая игра целиком (рендер, UI, против компьютера)

## Что делает фаза

Собирает крестики-нолики в цельную игру: рендер фигур на Viewport, Vue-UI игры
(баннер хода/результата, реакция на выбор клетки), запись в реестр и форма
преднастройки, режим против компьютера. Это **первый щупабельный релиз**:
запускаешь игру из меню и играешь против компьютера.

**Готово** — значит: игра есть в списке, преднастройка запускает партию против
компьютера; ходы ставятся кликом по полю; фигуры, линия победы и последний ход
видны; баннер показывает, чей ход и результат; игровое меню (платформы) работает.

## Принятые решения

### D1. Vue-UI игры — в `src/ui/games/<id>/`, реестр по id

Архитектурный тест (`architecture.test.ts:82-88`) **запрещает импорт `vue` под
`src/games/**`**. Поэтому UI игры живёт в `src/ui/games/tic-tac/`, а соответствие
«id игры → Vue-компонент» задаётся явным реестром `src/ui/games/registry.ts` (по
образцу реестра иконок/контроллов). Платформа монтирует компонент активной игры в
слой 2 (`LayerGameUi`).

Обоснование: правило архитектуры однозначно; реестр — принятый в проекте приём
(`ui/icons`, `ui/form`). Отклонено: отдавать Vue-компонент из записи игры
(`games/*/index.ts` нарушил бы тест); Vite-glob по UI (сложнее, выгоды нет).

### D2. Рендер: `Session.draw(frame)` → `Game.draw(state, frame)`

Игра stateless — состояние партии хранит `Session`. Значит, рендер инициирует
сессия: `Session.draw(frame)` вызывает `game.draw(gameState, frame)`. Контракт
`GameRenderFrame` (ctx, camera, bounds, size, dpr, toScreen/toWorld) объявляется в
ядре `src/core/game/render.ts` и использует типы камеры из `core/viewport`. Базовый
`Game.draw` — no-op по умолчанию. Viewport-компонент отдаёт свой `ViewportFrame` —
структурно совместим.

Обоснование: PROJECT.md:156 («`Game` … рендер»), PROJECT.md:228-234 (сессия даёт
игре интерфейс отрисовки); рендер без состояния невозможен, а состояние у сессии.
Отклонено: хранить состояние в игре (нарушило бы immutability-контракт `applyMove`);
класть `CanvasRenderingContext2D` в контракт UI (дубль типа).

### D3. Выбор клетки: сервис `boardInput`, а не знание Move в платформе

Viewport эмитит `pick` с мировыми координатами. Платформа не знает форму хода,
поэтому composition root предоставляет сервис `boardInput` (колбэк-обработчик);
`LayerBoard` зовёт его на `pick`. UI игры (D1) ставит обработчик на монтировании и
снимает на размонтировании: клик по клетке → `sessionAccess.makeMove(человек, {x,y})`.

Обоснование: принцип 7a (UI-адаптер дёргает ядро; ядро не знает UI) и «ход —
дело игры». Отклонено: платформа напрямую строит `{x,y}` (протечка формы хода в
ядро); `Game` сам ловит клики (игра — не UI).

### D4. Преднастройка и запуск против компьютера

Форма игры (`getSetupForm`): группа «Режим» — кнопка «С компьютером»; контролл
уровня ИИ (`select`/`number` 0..4). `attachEnvironment` подписывается на сигналы:
читает уровень из формы, ставит `game.level`, зовёт `lobby.defaultPlayers({humans:1,
computers:1})` и `environment.launch(players)`. Имя человека — из глобальных
настроек (как в `test-game`).

Обоснование: `test-game/game.ts:171-207` — рабочий образец пути через окружение;
лобби уже реализовано (фаза 03). Отклонено: отдельный режим «один/двое» в этой
фазе (хот-сит — 09).

### D5. Рейтинг/сложность — свойство игры, персистентность отложена

`getPropertySchema` объявляет свойство `level` (0..4). Математика рейтинга
(`difficulty.ts`) подключается, но **запись рейтинга в `game/<id>` не входит** в
фазу: сначала нужен работающий релиз. Пишем в BACKLOG.

Обоснование: BACKLOG «игровые свойства не персистятся»; принцип 1a (рабочий код
важнее). Отклонено: тянуть хранилище рейтинга сейчас (не блокирует релиз).

### D6. Конфетти и полировка — вне фазы

Конфетти (`tic-confetti.js`) в BACKLOG помечено «полировка, не блокер» — не
берём. Анимации — минимальные.

Обоснование: BACKLOG:44; ROADMAP 11 — «полировка» позже.

## Отклонённые варианты

| Вариант | Почему отклонён |
| --- | --- |
| Vue-UI из записи игры | Нарушает архитектурный тест (D1) |
| Рендер без состояния (только frame) | Игре нужно состояние, оно у Session (D2) |
| Платформа строит `{x,y}` сама | Протечка формы хода в ядро (D3) |
| Рейтинг в хранилище сейчас | Не блокирует первый релиз (D5) |
| Конфетти и анимации | Полировка, BACKLOG (D6) |

## Объём фазы

**Делаем:** контракт `Game.draw`/`Session.draw`; рендер фигур крестиков-ноликов;
токены `--board-x/--board-o`; реестр записи и форма преднастройки; реестр UI игр и
монтаж в слой 2; UI игры (обработка клика, баннер хода/результата); сервис
`boardInput`; режим против компьютера; тесты и браузерная приёмка.

**Не делаем:** персистентность рейтинга (D5), конфетти/полировка (D6), демо (08),
хот-сит (09), сеть (10).
