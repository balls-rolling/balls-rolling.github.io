# CONTEXT — Фаза 08: фоновое демо

## Что делает фаза

На фоне приложения постоянно идёт **живая партия одной из игр** (случайная из
реестра), а поверх неё открыто главное меню. Демо — обычная сессия с параметром
`demo`, флаг `isDemo` ставит сессия; способ демо решает игра. На поле нет
игрового UI: ни баннера, ни кнопки меню.

**Готово** — значит: при запуске за меню видна играющая партия ИИ vs ИИ (не одна
картинка, а движение); после окончания демо продолжается новой партией; запуск
настоящей игры сменяет демо; в демо нет баннера и игрового меню.

## Принятые решения

### D1. Состав демо объявляет игра: `Game.getDemoPlayers()`

Базовый `Game` получает метод `getDemoPlayers(): readonly PlayerInit[] | null`
(по умолчанию `null`). Платформа выбирает **случайную** запись, у которой игра
объявляет демо, и строит сессию с этими игроками. Крестики-нолики возвращают двух
компьютеров.

Обоснование: PROJECT.md:174,180 — «сессия сама запускает своё демо», «платформа не
решает, как именно игра себя демонстрирует». «Отдельной сущности стратегии демо»
нет — метод возвращает данные состава, а сам способ (ИИ vs ИИ) следует из обычных
`chooseMove`/агентов. Отклонено: платформа сама создаёт двух computer-игроков
(решала бы способ демо за игру).

### D2. `Platform.createDemoSession()`

Платформа получает метод, который перебирает записи реестра, поднимает игру,
спрашивает `getDemoPlayers()`, и на первой подходящей создаёт `Session` с
`options.demo`. Возвращает `Session | null`. Кто и когда запускает — решает
composition root. Метод не знает UI.

Обоснование: выбор случайной игры и создание сессии — дело платформы
(PROJECT.md:168). Отклонено: логика выбора в `main.ts` (платформа — её место,
тестируемость).

### D3. Граница слоёв: поле + диалоги всегда, игровой UI — нет

Слой поля (Viewport) монтируется всегда. Слой игрового UI (баннер игры, слот
сессии с кнопкой меню, уведомления слоя 2) **не монтируется в демо**. Слой
диалогов монтируется всегда — иначе главное меню поверх демо не показать.

Обоснование: наблюдаемое требование ROADMAP 08 «меню поверх живой партии; на
поле нет ни баннера, ни игрового меню» и PROJECT.md:17-18 (меню — диалог поверх
демо). **Расхождение с буквой PROJECT.md:243-245** («в демо не монтируются слои
2 и 3»): слои глобальные, а меню — диалог слоя 3; читаем «слои 2 и 3» как
**собственные UI/диалоги демо-игры**, а не платформенное меню. Зафиксировано.

### D4. Жизненный цикл: перезапуск после партии

Когда демо-партия завершается, composition root запускает новую с той же сессией
(`restart()`) через небольшую паузу. Пауза при скрытой вкладке (экономия CPU) —
в BACKLOG: не блокирует результат.

Обоснование: ROADMAP 08 «меню поверх живой партии» — живой фон не должен замирать;
BACKLOG «поведение фонового демо» оставлен как хвост.

### D5. Демо крестиков-ноликов: два компьютера, средний уровень

`getDemoPlayers` возвращает двух компьютеров («Компьютер 1/2»); у экземпляра
демо-игры выставляется `level = 2`, `missWin = false` (партия должна завершаться,
чтобы был перезапуск). Имена — нейтральные.

Обоснование: PROJECT.md:122-123 (демо — ИИ против ИИ). `missWin` существует для
демо-ошибок, но при нём партия может не завершаться; «средний» уровень даёт
конечную живую партию. Отклонено: `missWin` для обоих (риск бесконечной партии).

### D6. Новых зависимостей нет

Выбор случайной игры, слои и перезапуск — нативный код; ничего не добавляем.

## Отклонённые варианты

| Вариант | Почему отклонён |
| --- | --- |
| Платформа сама создаёт демо-игроков | Решала бы способ демо за игру (D1) |
| Логика демо в `main.ts` | Место платформы, тестируемость (D2) |
| Монтировать весь UI в демо и прятать CSS | DOM/инертность лишние (D3) |
| `missWin` обоим ИИ | Партия может не завершиться (D5) |
| Пауза по скрытой вкладке сейчас | Хвост, не блокирует (D4) |

## Объём фазы

**Делаем:** `Game.getDemoPlayers`; `Platform.createDemoSession`; запуск демо в
composition root + перезапуск после партии; граница слоёв (скрыть игровой UI в
демо); состав демо крестиков-ноликов; тесты.

**Не делаем:** пауза/CPU-бюджет демо (BACKLOG), «что показывать игре без
естественного демо» (решение игры, BACKLOG), хот-сит (09), сеть (10).
