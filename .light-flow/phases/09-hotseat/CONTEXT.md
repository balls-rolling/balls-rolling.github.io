# CONTEXT — Фаза 09: локальный хот-сит

## Что делает фаза

Добавляет режим игры **вдвоём за одним экраном**: две локальные «человеческие»
сессии, ход переходит по очереди, баннер показывает, чей ход. Сеть не нужна —
транспорт обоих `local`.

**Готово** — значит: из преднастройки запускается «Двое за экраном»; игроки
ходят по очереди кликами; баннер меняет имя; игровое меню предлагает «Сдаться и
выйти» (партия на несколько игроков).

## Принятые решения

### D1. Хот-сит — это состав из двух локальных людей

Ничего нового в ядре: сессия уже принимает любое число игроков и чередует ход
(`Session.nextPlayer` делегирует игре). Режим — кнопка в форме преднастройки
(«Двое за экраном»), обработчик зовёт `lobby.defaultPlayers({ humans: 2 })`.
Оба игрока — `human`/`local`.

Обоснование: `local.ts`/`players.ts` уже дают детерминированный состав на N
человек; ROADMAP 09. Отклонено: отдельный механизм передачи хода (лишнее —
очередь уже в сессии).

### D2. Модель игрока не пересматривается

ROADMAP упоминает пересмотр модели игроков в фазах 09–10 (в исходнике `kind`
смешивал агента и транспорт). **В платформе это уже сделано** (D7 фазы 02):
`agent` (`human`/`computer`) и `transport` (`local`/`remote`) — разные поля;
игровые свойства (глиф, рейтинг) выражаются схемой `PropertySchema`. Глиф
крестиков-ноликов остаётся **состоянием партии** (какой стороной ходит игрок —
часть правил, а не свойство личности). Рейтинг как свойство и его персистентность
— в BACKLOG (не блокирует).

Обоснование: PROJECT.md:69-72 (плановая модель), `player.ts:1-18`. Отклонено:
переносить глиф в свойства игрока (дублирование состояния; правила читают глиф из
state).

### D3. Баннер показывает имя текущего игрока

Уже реализовано (`TicTacToeUi`): «Ходит <имя>» / «Победил <имя>». Для хот-сита
достаточно. Отдельного экрана «передайте ход» не делаем — оба за одним экраном.

Обоснование: ROADMAP 09 «баннер „чей ход“»; минимализм.

### D4. Переименование игроков — вне фазы

Имена берутся из состава («Игрок» из настроек + «Гость 1»). Редактирование имён в
лобби/преднастройке — не блокирует хот-сит; при необходимости отдельной задачей.
Отклонено: тянуть UI переименования сейчас.

## Отклонённые варианты

| Вариант | Почему отклонён |
| --- | --- |
| Отдельный механизм передачи хода | Очередь уже в сессии (D1) |
| Глиф как свойство игрока | Часть правил, дублирует состояние (D2) |
| Экран «передайте ход» | Оба за одним экраном (D3) |
| UI переименования игроков | Не блокирует (D4) |

## Объём фазы

**Делаем:** кнопка «Двое за экраном» в форме преднастройки + обработчик запуска
двух локальных людей; тесты формы/запуска; браузерная проверка.

**Не делаем:** сеть (10), переименование игроков (D4), персистентность рейтинга
(BACKLOG).
