# CONTEXT — Фаза 01: Каркас

## Что делает фаза

Git-репозиторий инициализирован (`main`, коммитов нет). Создаётся рабочий каркас: сборка `vite + vue + ts`, prettier, базовая тема с токенами. **Готово** — `npm install` проходит, `vue-tsc` без ошибок, `vite build` собирается, в браузере тема ОС light/dark и подхваченный системный акцент. Портируется `theme/palette.js` из исходника.

## Принятые решения

- **D1. Структура каталогов — по слоям.** `src/core/` (ядро: Game-платформа, базовые классы, интерфейсы, Session, Player, хранилище, палитра), `src/ui/` (универсальный инструментарий: сервисы диалогов/окон/панелей и компоненты), `src/games/` (игры), `src/styles/` (токены, базовые стили). Игра лежит в папке со **свободным именем**, название хранится **внутри** как `id` и `label`; нумерации `game1`/`game2` нет — id от папки не зависит.
- **D2. Ядро, UI и игры разделены по ответственности.** Ядро — чистые классы/функции/интерфейсы, поведение и данные. `ui/` — универсальный инструментарий, не знающий назначения; связи устанавливает `Game`. Специфика рождается в момент использования. Игровое окружение — то, что передаётся сессии; игры работают только с интерфейсами окружения, свои инструменты добавляют плагинами. **`Game` не знает ни одной конкретной игры** — только *как узнать* доступные, работает с записями.
- **D3. Окружение собирается целиком, песочница отменена.** Заглушки (Null Object) и capability-граница **отменены**: разработка в одном проекте, игра получает всё, что запросила. Граница демо — **не то, что игра может, а какие слои смонтированы**.
- **D4. Три визуальных слоя, одна страница.** Без перезагрузок и переходов. Слой 1 — игровое поле (canvas); слой 2 — игровой UI + общие функции поверх (меню, во весь экран); слой 3 — диалоги и окна (верхний). В демо слои 2 и 3 не монтируются, остаётся слой 1 с UI игры внутри поля.
- **D5. Список игр — на этапе сборки.** `Game` получает список из папки `games`; ожидается генерация JS при сборке. Кандидат — `import.meta.glob` в Vite (**проверить в execute**). Формат записи: id, лейбл, точка входа, плагины окружения, точка демо; у плагинов есть точка входа.
- **D6. Отложено сознательно.** `pinia` — **не подключаем** (состояние — composables); ESLint — позже, сейчас только prettier без конфликта форматирования; vitest — фаза 06; имя каталога `balls-rolling` — оставляем.

## Отклонённые варианты

- `games/game1`, `games/game2` — имена теряют смысл, id не зависит от папки (D1).
- Заглушки Null Object для демо — игра в том же проекте, изоляция не нужна (D3).
- Capability-песочница — изоляция отнимает больше, чем даёт (D3).
- Статический список игр импортами — мешает отложенной загрузке и подключению собранных игр.
- Подключение уже собранных игр по URL — цена: общая часть как версионируемый пакет, запрет импорта внутренностей, совместимость версий; не в объёме (контракт единой точки входа фиксирует совместимость на будущее, D5).
- `pinia` для состояния — лишняя абстракция над composables (D6).
- ESLint на старте — нечего проверять; prettier настроен без конфликта на будущее (D6).

## Что делаем на этой фазе

1. Инициализация проекта vite + vue + ts, запуск и проверка сборки.
2. Prettier, совместимый с будущим ESLint.
3. `styles/`: токены темы — переносятся `--bg-1/2/3`, `--bg-m1`, `--card`, `--fg`, `--line`, `--accent`, `--accent-2`, `--ok`, `--danger`, `--shadow`, `--radius`, `--radius-sm` и приём `color-mix(in oklch, ...)` под фиксированный тёмный текст ради контраста в обеих темах.
4. Палитра: `prefers-color-scheme` + проба системного `AccentColor` через скрытый элемент + фолбэк `#3da96a`, реакция на смену системной темы.
5. Три слоя как заготовка каркаса, без наполнения, чтобы границы зафиксировались в коде до фазы 02.
6. Критерий готовности: `vue-tsc` чист, `vite build` собирается, тема переключается вместе с ОС, акцент подхватывается.

## Открытые вопросы

- Точная структура `Game` как синглтона и как он поднимает UI-контролы (главное меню, диалоги) — основное содержание фазы 02; на 01 нужна только заготовка слоёв.
- Формат записи игры и механизм получения списка из `games/` — проверить в execute; на эту фазу влияет только базовая согласованность импортов.
- Node-версия в `package.json`: свежие vite и `vue-tsc` требуют современного Node; в соседнем `billiards-together` — `^22.18.0 || >=24.12.0`; решить в execute.
