# CONTEXT — Фаза 09: локальный хот-сит

## Что делает фаза

Добавляет режим игры **вдвоём за одним экраном**: две локальные «человеческие»
сессии, ход переходит по очереди, баннер показывает, чей ход. Транспорт обоих
`local`.

**Готово:** из преднастройки запускается «Двое за экраном»; игроки ходят по
очереди кликами; баннер меняет имя; игровое меню предлагает «Сдаться и выйти».

## Принятые решения

- **D1.** Хот-сит — состав из двух локальных людей: кнопка в форме преднастройки
  зовёт `lobby.defaultPlayers({ humans: 2 })`; ядро не меняется — сессия уже
  принимает любое число игроков и чередует ход (`Session.nextPlayer` делегирует
  игре), ROADMAP 09.
- **D2.** Модель игрока не пересматривается: `agent` (`human`/`computer`) и
  `transport` (`local`/`remote`) уже разделены (D7 фазы 02); игровые свойства — через
  `PropertySchema`; глиф крестиков-ноликов остаётся состоянием партии, а не свойством
  личности; рейтинг в BACKLOG — PROJECT.md:69-72, `player.ts:1-18`.
- **D3.** Баннер показывает имя текущего игрока («Ходит <имя>» / «Победил <имя>»),
  уже реализовано в `TicTacToeUi`; отдельный экран «передайте ход» не делаем — оба
  за одним экраном.
- **D4.** Переименование игроков вне фазы: имена из состава («Игрок» из настроек +
  «Гость 1»).

## Отклонённые варианты

- Отдельный механизм передачи хода — очередь уже в сессии (D1).
- Глиф как свойство игрока — часть правил, дублирует состояние (D2).
- Экран «передайте ход» — оба за одним экраном (D3).
- UI переименования игроков — не блокирует (D4).

## Объём фазы

**Делаем:** кнопка «Двое за экраном» в форме преднастройки + обработчик запуска двух
локальных людей; тесты формы/запуска; браузерная проверка.

**Не делаем:** сеть (10), переименование игроков (D4), персистентность рейтинга
(BACKLOG).
