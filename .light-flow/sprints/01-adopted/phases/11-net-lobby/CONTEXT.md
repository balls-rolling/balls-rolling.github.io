# CONTEXT — Фаза 11: сетевое лобби

## Что делает фаза

Заменяет минимальный обмен кодами полноценным лобби: приглашение **ссылкой и QR**,
состав под управлением хоста (список, выгон), кнопка **«Начать»** (партия — без
автостарта), **лобби ожидания** у гостя, имена и реванш. Разрыв/восстановление —
фаза 12.

**Готово:** хост открывает лобби, копирует ссылку/QR; гость подключается по ссылке
(или коду), оба видят состав; хост выгоняет и жмёт «Начать»; партия стартует у всех
только после этого; после партии — реванш; гость может выйти до старта.

## Принятые решения

- **D1. Состав ведёт хост (источник истины):** игроки шлют `join` (имя; id выдаёт
  хост), хост хранит список и рассылает изменения; гость только отображает; выгон —
  решение хоста. Причина: ответ пользователя; один источник исключает рассинхрон.
  Отклонено: каждый ведёт список.
- **D2. Выгон и выход:** выгнанный исчезает у всех и получает уведомление «вы
  исключены» + уходит в меню; гость может `leave` до старта; уведомления — через
  существующий центр. Отклонено: молчаливое исчезновение.
- **D3. «Начать» — только по кнопке хоста** (активна при ≥2 игроков; автостарта
  нет; фаза 10 с автозапуском — неверное поведение). Причина: ответ пользователя.
- **D4. Лобби ожидания у гостя:** после подключения видит состав и может выйти;
  партия не начинается до `start`. Причина: ответ пользователя.
- **D5. Протокол лобби отдельно от игрового:** `join`, `players`, `kick`, `start`,
  `leave`, `rematch-offer/accept/decline`; игровые (`move`, `surrender`) — как есть;
  порядок и id задаёт хост через `players`/`start` (совпадение очереди хода).
  Причина: чистое разделение; `net/protocol.ts` остаётся игровым. Отклонено: один
  общий протокол.
- **D6. Приглашение — ссылка со спец-query:** `?open=net_game&game_id=…&offer=…`
  (`offer` base64url). Платформа читает query, ищет именованный `open`-обработчик
  (`net_game`), выполняет (находит/грузит игру, открывает лобби, подставляет
  `offer`); неисполнимый query → URL очищается; ошибка обработчика → обычная
  загрузка + уведомление. Причина: ответ пользователя; механизм расширяемый.
  Отклонено: только текстовая вставка.
  _Реализовано (11):_ битый `offer` → «Плохой код приглашения» в лобби;
  уведомление — только если `open`-обработчик бросил.
- **D7. QR: генерация из ссылки; скан по ресёрчу; QR и для ответа.** QR кодирует
  ту же ссылку; генерация — библиотекой. Скан — генеративные не умеют; через
  нативный `BarcodeDetector` (не везде); иначе только ссылка/код. Симметрично гость
  показывает QR ответного кода (хост сканирует/вставляет). Ёмкость: код ~783
  симв., ссылка ~850 байт; byte-режим QR L 2953/M 2331/H 1273 → L/M с запасом;
  уровень **L/M**, крупный рендер, риск плотного кода — размер/контраст +
  текстовый код. Причина: ответы пользователя; «нативное лучше».
  _Реализовано (11):_ данные сжимаются нативным `deflate-raw` (`CompressionStream`)
  перед base64url — код приглашения **560** вместо 783 (префикс `z`/`u`, ~28%).
  QR не показывается постоянно: кнопка «QR» открывает отдельный диалог поверх лобби,
  генерация в момент открытия, закрытие — флексовая кнопка внизу; то же для ответа.
- **D8. Реванш:** `rematch-offer/accept/decline`; предлагает хост, согласие обеих
  сторон, сессия перезапускается (`restart`) с тем же составом; отказ — игра
  остаётся завершённой (доступен выход). Причина: наследие `net/protocol.js`.
  Отклонено: без реванша.
- **D9. Реконнект/восстановление — фаза 12:** здесь только закладываем расширяемость
  протокола лобби под будущий `resume`. Причина: решение пользователя о разбиении.

## Отклонённые варианты

| Вариант | Почему отклонён |
| --- | --- |
| Автостарт при подключении | Неверное поведение (D3) |
| Список ведёт каждый сам | Рассинхрон составов (D1) |
| Молча выгонять | Пользователь не понимает, что произошло (D2) |
| Один протокол на лобби и игру | Связность и путаница (D5) |
| Только текстовый код без ссылки | Менее удобно; ссылка с `open` решает (D6) |
| Скан QR любой ценой | Генераторы не сканируют; нативный не везде (D7) |

## Объём

**Делаем:** лобби-UI (хост и гость), состав/выгон/«Начать», лобби-протокол,
приглашение ссылкой через `open`-обработчик, QR-генерация (и скан, если ресёрч
подтвердит), имена, реванш, уведомления о выгоне.

**Не делаем:** разрыв и восстановление (12), деплой (13), редактирование имён,
сеть >2 (универсальность сохраняем, проверяем на двух).

## Открытые вопросы

Нет — решений достаточно. На plan — ресёрч: QR-библиотека и скан, форма реестра
`open`-обработчиков, лимиты длины ссылки.
