# PLAN — Фаза 03 «Ядро: физика»

**Тесты фазы: y.** Физика — чистое ядро, тесты в `node` (vitest). Новых
npm-зависимостей нет; платформенный код не трогаем.

**Цель:** бильярд доведён до «партия отыгрывается в коде»: удар параметрами
прогоняется до полного покоя, результат детерминирован, соударения и лузы
корректны, состояние сериализуется — без DOM.

## Задачи (в порядке исполнения)

**T1. Константы физики.** Единый источник чисел решателя: фиксированный шаг,
замедление качения, реституции «шар-борт» и «шар-шар», тангенциальное
демпфирование борта, порог и число тиков покоя, кап субшагов, допуск
позиционной коррекции. **Требование:** шаг фиксирован (R3); прочие значения —
playtest. Готово: тест проверяет инварианты (шаг > 0 и неизменен; реституции в
[0,1); все числа конечны и положительны), а не магические значения.
Файлы: `constants.ts` (+ тест). Зависит: нет. Параллельно T2. tests: y.

**T2. Геометрия луз и борта для физики.** У каждой лузы доступны центр рта и
внешняя нормаль (от центра стола наружу); у каждого отрезка стола — нормаль
внутрь поля. **Требование (P7):** захват считается по линии рта наружу и
боковому допуску. **Guidance:** вывести из готовой геометрии (ось лузы сейчас
приватна), не пересчитывать в решателе. Готово: тест — центр рта = середина
`noseA/noseB`, нормаль единичная и наружу; у носов нормаль внутрь; у боковых —
вдоль короткой оси, у угловых — диагонально. Файлы: `geometry.ts` (+ тест).
Зависит: нет. Параллельно T1. tests: y.

**T3. Движение, замедление, покой.** Чистая функция свободного движения:
интегрирование позиции по скорости, замедление до полной остановки за конечное
время, явное обнуление скоростей при покое (порог + N тиков). **Требование:**
без эффектов спина (P3); внутри шага нет времени и случайности (R3); покой —
событие, а не асимптота. **Guidance:** псевдо-качение постоянным замедлением;
счётчики покоя — локально в прогонке. Готово: тест — шар приходит к точному нулю
за ограниченное число тиков, не проскакивая знак и не дрожа; покоящийся остаётся
нулевым; нет NaN; время/случайность не читаются. Файлы: новый `physics.ts`
(+ тест). Зависит: T1. tests: y.

**T4. Соударение шар-борт.** Отскок от носов и облицовок по нормали внутрь поля
с реституцией и тангенциальным демпфированием; позиционная коррекция без провала
за линию носа глубже допуска. **Требование (R3):** нет провала/туннелирования.
**Guidance:** нормали отрезков из T2; обрабатывать все сегменты. Готово: тест —
перпендикулярный отскок гасит нормальную скорость, касательный теряет часть
тангенциальной; после отскока центр не ближе `R−допуск` к линии; шар не выходит
за внешние границы. Файлы: `physics.ts`. Зависит: T2, T3. tests: y.

**T5. Соударение шар-шар.** Импульс по нормали между шарами равной массы +
позиционная коррекция перекрытия с допуском; пары в стабильном порядке.
**Требование (R3):** детерминизм, энергия не растёт. Готово: тест — центральный
удар передаёт скорость; суммарный импульс сохраняется в допуске; энергия не
растёт; после контакта шары не перекрываются; результат не зависит от порядка
пар; два перекрытых покоящихся шара разъезжаются. Файлы: `physics.ts`.
Зависит: T3. tests: y.

**T6. Захват луз.** Реализовать правило **P7**: шар забит, когда центр пересёк
линию рта наружу и попал в боковой допуск; забитый деактивируется. **Требование
(P7, R1):** никакого круга-ловушки, промахи не глотаются. **Guidance:**
центр/нормаль из T2. Готово: тест — шар вдоль длинного борта мимо боковой
остаётся активным; прижатый к борту в угловую — забит; пересечение линии в
стороне от зева — не забит; захват только при пересечении наружу. Файлы:
`physics.ts`. Зависит: T2. tests: y.

**T7. Субшаговый шаг и замороженный порядок.** Единый шаг над состоянием:
субшаги по максимальной скорости (не более доли радиуса за субшаг, с капом) и
порядок «интеграция → захват луз → стол → пары → сон». **Требование (R3):**
фиксированный шаг, замороженный порядок, отсутствие туннелирования,
независимость от разбиения на вызовы. Готово: тест — быстрый шар не проходит
сквозь борт и другой шар; один удар порциями по N шагов и одним вызовом даёт
идентичный результат; субшагов не больше капа; при нулевой скорости субшаг
ровно один. Файлы: `physics.ts`. Зависит: T3–T6. tests: y.

**T8. Дескриптор удара и прогон до покоя.** Удар параметрами (направление +
сила) и функция, прогоняющая партию от удара до полного покоя фиксированными
шагами с верхним лимитом и ясным исходом «покой / лимит». **Требование (P6):**
удар программный, без UI; **P3:** спин не действует, но форма допускает его
позже. Готово: тест — разные удары дают разные траектории; один удар дважды из
одного состояния даёт идентичное финальное состояние; прогон завершается точным
покоем (без NaN) за ограниченное число шагов; невалидный дескриптор отклоняется.
Файлы: `physics.ts` (или отдельный shot-модуль) + тест. Зависит: T7. tests: y.

**T9. `applyMove`: удар как ход и раунд-трип.** `BilliardsGame.applyMove`
принимает удар, синхронно прогоняет до покоя и возвращает новое состояние.
**Требование (P4):** правила и переход хода не здесь — `turn`/`nextPlayer` не
трогаем; при отклонении состояние не меняется; формат сериализации не меняем.
**Guidance:** тонкая обёртка над T8; `chooseMove` прежний. Готово: тест —
принятый удар меняет состояние и гасит скорости; `turn` прежний; отклонённый
удар возвращает тот же объект; `serialize→deserialize` после удара структурно
равен; нулевая сила — зафиксировать одно поведение. Файлы: `game.ts` (+ тест).
Зависит: T8. tests: y.

**T10. Сквозная проверка.** Без новых файлов: `npm test`, `npm run typecheck`,
`npm run build`; `architecture.test.ts` зелёный; в физике статически нет
`window`/`document`/`Math.random`/`Date.now`; вручную собрать в коде партию
(старт → несколько ударов → все в покое, состояние сериализуется). Готово:
команды зелёные; неавтоматизируемое — в отчёт как непроверенное. Зависит: T9.
tests: n.

## Порядок и параллельность

T1 ‖ T2 → T3 → (T4 ‖ T5 ‖ T6) → T7 → T8 → T9 → T10. Критический путь:
T1→T3→T7→T8→T9→T10. T4/T5/T6 правят общий `physics.ts` — при одном исполнителе
последовательно.

## Затрагиваемые файлы

- `src/games/billiards/constants.ts`, `geometry.ts` (правки)
- `src/games/billiards/physics.ts` (новый)

## Решения

| # | Решение | Выбор и цена |
| --- | --- | --- |
| 1 | Модель движения без спина | Псевдо-качение постоянным замедлением: детерминизм, конечное время покоя, минимум состояния (P2). Цена: нет тонкости «скольжение→качение»; апгрейд — фаза 05 |
| 2 | Где живут счётчики покоя | Локально в прогонке удара, не в сериализуемом состоянии — формат `state.ts` не меняется. Цена: в фазе 04 (пошаговый цикл) их придётся переселить в рантайм |
| 3 | Где нормали и захват | Derived-данные геометрии (`geometry.ts`). Цена: геометрия растёт; выигрыш — решатель не дублирует ось и не считает в горячем цикле |
| 4 | Форма удара | Свой billiards-move: направление + сила; спин — опционально позже. Платформенный `Move` непрозрачен, ядро не затрагиваем |
| 5 | Библиотека физики | Не берём (P1): круговые аппроксимации, нет сукна/борта, потеря контроля над детерминизмом. Свой решатель невелик |
| 6 | Субшаг и кап | Дробим по максимальной скорости (ориентир ≤~0.5R за субшаг, кап), чтобы сближение пары < диаметра. Цена: на разбитии больше субшагов; кап и тест закрывают худший случай |
