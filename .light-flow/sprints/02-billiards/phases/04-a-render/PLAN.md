# PLAN — Подфаза 04-a «Рендер стола и шаров»

Часть фазы 04 «Рендер и UI партии» (родительский `CONTEXT.md` — у фазы).
**Тесты фазы: y** (ядро/контракт; UI — визуально). Платформу трогаем **точечно** —
это и есть свёрнутый пункт «игра объявляет потребность в зуме/пане».

**Цель:** стол и шары рисуются «нормально» на платформенном `Viewport`, всегда
целиком (фиксированная камера), без зума/пана и без платформенной сетки — игра
сама объявляет эти потребности.

## Задачи (в порядке исполнения)

**T1. Декларация потребностей камеры в контракте игры.** Необязательный метод
`Game.getViewOptions()` с дефолтом, сохраняющим текущее поведение платформы
(зум/пан/сетка включены). **Требование:** игра сама объявляет, что ей нужно от
камеры/поля (Q4, свёрнутый пункт бэклога). Готово: тест — дефолт для игры без
переопределения; бильярд объявляет зум/пан/сетку выключенными. Файлы:
`src/core/game/game.ts` (+ тест). Зависит: нет. tests: y.

**T2. Проброс декларации в `Viewport`.** `LayerBoard` читает `game.getViewOptions()`
текущей сессии и передаёт в `Viewport` (например, `controls`/`showGrid`/режим
панорамы). **Требование:** бильярд получает фиксированное поле без зума/пана/сетки.
Готово: при выключенном зуме/пане у `Viewport` не видно кнопок зума и поле не
панорамируется; при выключенной сетке её нет. Файлы: `src/ui/shell/LayerBoard.vue`,
`src/ui/viewport/Viewport.vue`. Зависит: T1. tests: n (UI — визуально).

**T3. `Viewport`: отключаемые зум и пан.** Разделить «есть управление» на зум и пан
(сейчас один флаг `controls`): `zoom:false` убирает обработку колеса/кнопок,
`pan:false` — панорамирование указателем; не ломать игры, которым управление
нужно. **Требование:** декларация реально действует, а не игнорируется. Готово:
`Viewport` не зумит/не панорамирует при выключенных флагах; существующие игры
(крестики-нолики/тестовая) сохраняют поведение по умолчанию. Файлы:
`src/ui/viewport/Viewport.vue`. Зависит: T2. tests: n.

**T4. Нормальный рендер стола и шаров.** Рисование игры приводится к «нормальному»:
сукно, борта, лузы, разметка, шары с номерами; стол вписывается целиком
(fit-contain), фиксированная камера. **Guidance:** убрать ручную заливку-обёртку
для скрытия платформенной сетки (теперь сетка выключена декларацией); по
возможности использовать цвета из кадра/темы, а не только свои константы.
**Требование:** стол всегда целиком, игра рисует поле сама (Q1/Q4). Готово:
визуально стол с шарами отрисован, всегда целиком, без сетки. Файлы:
`src/games/billiards/render.ts`. Зависит: T3. tests: n (visual).

**T5. Проверка подфазы.** `npm run typecheck`, `npm test`, `npm run build`;
визуально: бильярд из меню — фиксированный стол целиком, без зума/пана/сетки;
крестики-нолики/тестовая — управление как раньше. Готово: команды зелёные,
визуальный факт зафиксирован (скриншот), неавтоматизируемое — в отчёт. Зависит:
T4. tests: n.

## Затрагиваемые файлы

- `src/ui/shell/LayerBoard.vue`, `src/ui/viewport/Viewport.vue` (проброс и режимы)
- `src/games/billiards/game.ts` (декларация бильярда)

- тесты рядом

## Решения

| # | Решение | Цена |
| --- | --- | --- |
| 1 | Декларация камеры — методом `Game.getViewOptions()` с дефолтом | Малое расширение контракта ядра; оправдано прямой просьбой пользователя |
| 2 | Рендер оставляем в игре (fit из `frame.size`), камеру платформы не используем | Без fit-contain в платформе; согласовано с Q1 «игра рисует поле» |
| 3 | Цвета — константы игры (как в фазе 02) | Токенов сукна/шаров в платформе нет; расширение темы — не в этой подфазе |
