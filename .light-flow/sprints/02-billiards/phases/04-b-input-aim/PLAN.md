# PLAN — Подфаза 04-b «Игровой цикл/анимация и ввод прицела»

Часть фазы 04 (родительский `CONTEXT.md` фазы 04; решения Q1–Q6). **Тесты: y**
(ядро-рантайм) + визуально. Платформу трогаем точечно (доступ к полю).

**Цель:** партия «оживает»: шары катятся по кадрам после удара, есть наведение и
кий; ввод — указателем, игра подписывается сама.

**Ключевое решение (sealed):** удар **засчитывается в сессию в момент удара**
(атомарно, как сейчас), а **конец удара для UI — завершение воспроизведения**;
переключение/обновление UI откладывается до конца анимации. Анимация — реплей уже
детерминированного результата (один `step`), а не новая правда.

## Задачи (в порядке исполнения)

**T1. Доступ игры к полю (платформа/UI, точечно).** Дать игре доступ к канвасу и
возможность просить перерисовку: расширить мост `boardInput` (`src/ui/board-input.ts`)
канвасом и `requestDraw`; `Viewport` экспонирует canvas; `LayerBoard` прокидывает
их в мост. **Требование (Q2):** игра подписывается на ввод сама. Готово: игра из
UI-слоя получает канвас и может попросить кадр; другие игры не затронуты. Файлы:
`src/ui/board-input.ts`, `src/ui/viewport/Viewport.vue`, `src/ui/shell/LayerBoard.vue`.
Зависит: нет. tests: n (UI).

**T2. Рантайм анимации в игре.** В `BilliardsGame` — несериализуемый рантайм:
кэш последнего отрисованного состояния, активный реплей, угол прицела. Методы:
`startShot(shot)` (взять текущее состояние, приложить удар, включить реплей),
`advance(dt): boolean` (фиксированный шаг + аккумулятор до покоя; вернуть «ещё
идёт»), `isAnimating()`, `setAim(angle)`/`getAim()`. **Требование:** игра ведёт
цикл, `draw` во время реплея рисует рантайм-кадр, иначе — переданное состояние;
сериализуемое `BilliardsState` не меняется. Готово: тесты — `startShot` включает
анимацию; `advance` продвигает и завершается покоем (`isAnimating=false`); один
удар, прогнанный `advance`, даёт то же состояние, что `applyShot`. Файлы:
`src/games/billiards/game.ts` (+ тест). Зависит: нет. tests: y.

**T3. Рендер прицела и кия.** `draw` рисует наведение: линию от битка по углу и
кий (простой прямоугольник/линия со смещением). **Guidance:** минимум, без
«рюшечек» (глубина/траектория — фаза 05). Готово: при заданном угле видно
направление и кий; без прицела — как раньше. Файлы:
`src/games/billiards/render.ts` (или новый `aim`-хелпер). Зависит: T2. tests: n.

**T4. UI-компонент бильярда: ввод и цикл.** `src/ui/games/billiards/BilliardsUi.vue`:
подписка на канвас (Pointer Events: `pointerdown/move/up/cancel`, порог тап/драг),
перевод координат в угол наведения, `setAim`; по удару — `startShot` + коммит в
сессию; rAF-цикл зовёт `advance(dt)` и `requestDraw()`; ввод заблокирован, пока
`isAnimating()`. Регистрация в `src/ui/games/registry.ts` (`billiards`). **Требование
(R4):** только Pointer Events, `pointercancel` без выстрела; конец удара — конец
реплея (sealed). Готово: целясь мышью, слышно/видно направление; удар анимируется;
во время анимации новый удар не берётся. Файлы: `src/ui/games/billiards/BilliardsUi.vue`
(новый), `src/ui/games/registry.ts`. Зависит: T1, T2, T3. tests: n (визуально).

**T5. Проверка подфазы.** `npm run typecheck`, `npm test`, `npm run build`;
визуально: наведение и кий, удар с анимацией шаров, ввод заблокирован во время
реплея, по завершении — кадр совпадает с итогом. Готово: команды зелёные,
скриншот/осмотр; неавтоматизируемое — в отчёт. Зависит: T4. tests: n.

## Решения

| # | Решение | Цена |
| --- | --- | --- |
| 1 | Рантайм анимации — в игре, `draw` предпочитает его во время реплея | игра получает рантайм (не сериализуемый); формулировку «stateless» уточняем комментарием |
| 2 | Удар засчитывается сразу; конец удара для UI — конец реплея | переключение UI откладывается; для ИИ/сети на будущее — учитывать |
| 3 | Игра сама подписывается на канвас через мост `boardInput` | малая правка UI-моста; канвас уходит в UI игры (это UI-слой) |
| 4 | Драйвер — фиксированный шаг + аккумулятор, кламп `dt`, лимит шагов | ~30 строк своего цикла; новых зависимостей нет |
| 5 | Прицел — в несериализуемом рантайме игры | наведение не в сохранении/сети (R4) |
