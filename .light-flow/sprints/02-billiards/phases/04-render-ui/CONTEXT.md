# CONTEXT — Фаза 04 «Рендер и UI партии» (разбита на подфазы)

Спринт 02 «billiards». Фаза разбита на 4 подфазы; обсуждение — одно на всю фазу,
`CONTEXT.md` родительский.

## Что делаем и когда фаза готова

Нормальный рендер стола на `Viewport` и UI партии: камера, прицел, кий, сила,
кнопка удара, панели игроков, меню и экран результата. **Готово**, когда партию
можно играть курсором: целиться, задавать силу, бить, видеть ход и результат.

## Решения

**Q1. Игра рисует поле сама; UI — через предоставленные интерфейсы.** Всё, что на
игровом поле, рисует игра; взаимодействие с UI — через интерфейсы платформы: игра
наполняет UI (кнопки/панели) и слушает их сигналы. Это продолжение D1/принципа 8
PROJECT.md.

**Q2. Ввод: игра получает канвас/события и подписывается сама.** Если игра имеет
доступ к канвасу, она сама подписывается на нужные pointer-события; иначе
платформа обязана пробрасывать события/давать интерфейс ввода. Решение: дать игре
доступ к вводу поля (канвас/события) — игра обрабатывает прицел сама.

**Q3. Цикл у игры.** Игра ведёт игровой цикл; UI-слой платформы гоняет кадры (rAF) и
через интерфейсы продвигает игру. Физика отдаёт чистый `step` (фаза 03); драйвер
реализуется в этой фазе (детали — в плане подфазы 04-b).

**Q4. Бильярд объявляет «зум/пан не нужны», стол фиксирован целиком.** Платформа
получает декларацию игры о потребности в камере (свёрнутый пункт бэклога
«игра объявляет потребность в зуме/пане»). Бильярд: фиксированная камера,
fit-contain, стол всегда целиком.

**Q5. Раскладка альбомная (D4).** В портрете UI разворачивается.

**Q6. База — без «рюшечек» (D3).** В фазе: прицел, кий, сила, удар, панели, меню,
результат. Спин/финты/lob/глубина превью — фаза 05.

**Q7. Тайминг удара (решение пользователя).** Физика считается сразу, но **удар
засчитывается в сессию в момент удара** (атомарно), а **концом удара для UI
считается завершение воспроизведения**; обновление UI (переключение/панели)
откладывается до конца анимации. Анимация — реплей детерминированного результата.

## Подфазы

- **04-a-render** — нормальный рендер стола и шаров на `Viewport`: сукно, борта,
  лузы, разметка, шары с номерами; фиксированная камера (стол целиком) и
  **декларация игры «зум/пан не нужны»** с пробросом в платформу.
- **04-b-input-aim** — игровой цикл/анимация и ввод прицела: доступ к канвасу/
  событиям, наведение, кий, движение шаров по кадрам.
- **04-c-force-shoot** — сила (слайдер/колесо) и кнопка удара, применение удара до
  покоя; панели игроков и инфо-бар хода.
- **04-d-menu-result** — игровое меню, экран результата, выход из партии; адаптивная
  альбомная раскладка с поворотом в портрете.

## Рассмотренные и отклонённые варианты

- Игра рисует через собственный canvas без платформы, камера/зум обязательны для
  бильярда, UI-компонент полностью вне интерфейсов платформы — отклонены (Q1–Q4).

## Открытые вопросы

- Точная механика доступа игры к канвасу/событиям (что именно отдаёт платформа) —
  в плане 04-a/04-b.
- Как UI продвигает цикл (вызов `advance` + инициирование перерисовки) — в плане 04-b.
