# PLAN — Подфаза 03-b «Панели игроков»

**Тесты фазы: y** (разложение игроков по сторонам и реестр виджетов — юнит;
вид — живьём, DOM в тестах нет).

**Цель:** платформенная **двойная панель участников** (слева хост, справа гость,
у кого ход — рамка) вместо строки «Ходит»; в зонах — **виджеты** (игра отдаёт
свой Vue-компонент по токену, как иконки/контроллы); бильярд кладёт в левую и
правую зоны инфо-бары игроков (места под забитые шары, очки, бонусы) и убирает
свою нижнюю плашку хода.

**Решение пользователя:** панель хода — **платформенная** (одна на игры);
сложные панели в зонах — **Vue-компонент игры**.

## Задачи (в порядке исполнения)

**T1. Разложение игроков по сторонам (ядро UI, чистое).** `ui/shell/players.ts`:
`sides(snapshot)` → `{ left, right, currentId }` — левый = `players[0]` (хост),
правый = `players[1]` (гость); при одном игроке правой стороны нет. Зависит: нет.
tests: y.
Done: функция покрыта тестом; игрок без пары не даёт второй стороны.

**T2. Платформенная панель участников.** `ui/shell/PlayersPanel.vue`: двойная
панель из снимка; текущий обведён рамкой; при одном игроке — одна половина.
`SessionHost` показывает её вместо строки «Ходит» и только если игра не отказалась
(`playersPanel !== false`). Зависит: T1. tests: n (вид — живьём).
Done: в бою видна двойная панель, у ходящего рамка; отказ игры (`false`) её скрывает.

**T3. Виджеты в зонах.** `Control.kind = "widget"` (значение — строковый токен):
`ui/widgets/WidgetControl.vue` (ищет компонент по токену), `ui/widgets/registry.ts`
(`token → Component`, `markRaw`, заморожен; неизвестный токен — запасной вид);
регистрация `widget` в реестре контроллов. Причина: сложную панель нельзя
выразить узлами формы, а Vue в ядро не пускаем — токен остаётся строкой.
Зависит: нет (параллельно T1–T2). tests: y.
Done: контролл-виджет рисует компонент по токену; неизвестный токен не падает;
тесты реестра зелёные.

**T4. Бильярд: инфо-бары в зонах.** `BilliardsGame.getUiLayout()`: слева — виджет
бара хоста, справа — виджет бара гостя; внутри — места «Шары», «Очки», «Бонусы»
(пусто, данные с правилами 05+). Убрать нижнюю плашку хода из `BilliardsUi`
(ход показывает платформенная панель); `playersPanel` больше не `false` —
платформенная панель бильярду нужна (отмена решения 03-a, решение пользователя).
Зависит: T2–T3. tests: y (у бильярда в схеме две зоны и нет отказа от панели).
Done: в бою слева и справа бары игроков с заголовками-местами; нижней плашки нет;
панель участников сверху показывает ход.

**T5. Живая проверка + отчёт.** Свежий билд: двойная панель и рамка хода; бары
игроков по краям; регрессия — **крестики и тест-игра** (новая панель им не
ломает партию/меню/выход). `typecheck`/`test`/`build`/`architecture`; REPORT.
Зависит: T1–T4. tests: y.
Done: контур EXIT=0; живьём подтверждено; регрессия чистая; REPORT.

## Забыто

- Отмена `playersPanel:false` у бильярда (решение 03-a) — осознанная, по слову
  пользователя; в 03-a это было подтверждено живьём, поэтому перепроверяем.
- Крестики и тест-игра получают новую панель участников — их ход теперь там.
- Виджет — строка-токен: Vue в ядро не протекает (принцип 7a).
- Бары — места; забитые/очки/бонусы не выдумываем (правила — 05+).
- Зона-виджет не должна перехватывать клики по полю (слой UI — `pointer-events`).

## Риски

- `SessionHost` и панель общие для всех игр: замена строки хода бьёт по крестикам
  и тест-игре — verify смотрит их живьём.
- Обратный разворот `playersPanel` у бильярда — риск для 03-a-статуса; фиксируем
  в отчёте 03-b.
- Виджет-компонент импортируется в UI-реестр явно (как иконки): забыть
  зарегистрировать токен → запасной вид, а не падение (проверяемо тестом).
