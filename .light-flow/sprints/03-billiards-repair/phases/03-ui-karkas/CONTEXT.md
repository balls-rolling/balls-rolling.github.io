# CONTEXT — Фаза 03 «Каркас UI и панели» (спринт 03)

Сплит (согласован): **03-a «Каркас UI и зоны»**, **03-b «Панели игроков»**,
**03-c «Координаты и нормы»**, **03-d «Экран партии по референсу»**.
Обсуждение одно на всех; планы — по подфазам.

## О чём фаза

Платформа даёт игре **декларативные зоны интерфейса** (верх/низ/лево/право),
экземпляр сессии получает интерфейсы взаимодействия с ними; бильярд раскладывает
по зонам меню, панели игроков и свои инфо-бары. Плюс — чистка прод-UI от
отладочного (`running`, `revision`), общий хелпер координат и наблюдаемые нормы
R4. Раньше фаза называлась «Раскладка и покрытие»; часть её пунктов закрыта:
«панель не на сукне» и «тест прицела» — в фазе 02.

**Целевой вид (слова пользователя):**
- Верхний бар: **меню в край влево**.
- По центру — **двойная панель**: слева главный игрок (хост), справа гость
  (второй); **кто ходит — обведён рамкой**.
- Ниже — панель бильярда: слева по левому краю инфо-бар хоста, справа по правому
  краю панель гостя; там **забитые шары, очки, бонусы** (сейчас — места;
  данные появятся с правилами, 05+).

## Решения (с причинами)

- **D1. Механизм зон — по аналогии с формой.** Ядро отдаёт схему (без Vue/DOM),
  UI строит по ней; у игры есть **спец-компонент** зоны с параметром направления
  (`horizontal`/`vertical`); в UI — **четыре** таких компонента (верх/низ/
  лево/право). Причина: форма уже так устроена (`core/form/types.ts`, реестр
  `ui/form/registry.ts`) — новую сущность не изобретаем, повторяем образец.
- **D2. Интерфейсы зон пробрасывает оболочка** экземпляру сессии игры (как
  `setup: FormHandle` в `GameEnvironment`): игра получает хендлы зон и кладёт
  туда контроллы/тексты, не зная DOM.
- **D3. Прод-UI без отладки (K4/M4).** `SessionHost.vue` показывает `state` и
  `revision` для всех игр — это внутренности платформы. Убрать из прода;
  «ходит X» — на совести игры (в бильярде — своя панель игроков). Меню остаётся.
- **D4. Отказ от стандартной панели участников.** В опции вида игры (рядом с
  `zoom`/`pan`/`grid`, `GameViewOptions`) добавить флаг отказа от стандартной
  панели участников: бильярд рисует свои панели. Причина: сейчас панель платформы
  дублирует игровую.
- **D5. Общий хелпер координат (M3).** Один источник `fit`/инсетов для рендера и
  ввода (`FIT_PADDING`, `bottomInset` уже заведены в 02-c) — чтобы не расходились
  (урок `ui-behavior.md` п.5).
- **D6. Наблюдаемые нормы R4 ([01-F1]).** Дописать в требования проверяемые
  нормы поведения UI (курсоры, крайние значения, стабильность геометрии, запрет
  перекрытия сукна и отладки в UI) — за них цепляется проверка.
- **D7. Заглушки-места** под забитые/очки/бонусы — рисуем сейчас, данные позже.

## Отвергнутые варианты

- «Дескриптор `{zone, component, order}`, платформа размещает» — отвергнуто:
  компонент-зона с направлением ближе к образцу формы и явнее.
- «Убрать верхний бар целиком» — отвергнуто: меню и колокольчик нужны; меню
  переезжает влево.
- Инсеты «как сейчас» (игра сама меряет) — отвергнуто: выносим в контракт.

## Подразумеваемое

- Зоны общие для всех игр: дефолт не должен ломать крестики и тест-игру
  (у них нет зон — пустые).
- Панель игроков: слева хост, справа гость; текущий обведён рамкой; для
  одиночной игры (тест-игра/крестики) хватает одной стороны.
- Инфо-бары — места; ничьи данные не выдумываем.

## Два списка

- **Forgot:** `SessionHost` общий — правка бьёт по крестикам/тест-игре; меню и
  колокольчик обязаны остаться доступными; у зон нужен дефолт «пусто»; бильярд
  опт-аут стандартной панели (D4) до появления своих панелей (03-b).
- **May break:** расширение `GameViewOptions` и `GameEnvironment` трогает все
  игры; перенос панелей ломает текущую плашку хода (02-c) — переносить, не
  дублировать; хелпер координат затрагивает `render.ts`/`BilliardsUi.vue`.
