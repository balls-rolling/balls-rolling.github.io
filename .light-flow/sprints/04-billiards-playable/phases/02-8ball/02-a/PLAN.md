# PLAN — Подфаза 02-a «Ядро правил 8-ball»

Статус: **утверждено пользователем 2026-10-16**. Исполняется.
2026-10-16 («весь режим 8-ball со всеми вариантами старта»), объём заведомо >10
задач — разбиение на подфазы: **02-a ядро правил; 02-b экраны + локальная игра;
02-c ИИ; 02-d сеть**. Старые фазы 03–05 роадмапа поглощаются подфазами 02
(перестройка роадмапа — вместе с утверждением плана). Детально планируется
только 02-a; планы 02-b/c/d — при запуске каждой. Подфазы наследуют
`../CONTEXT.md` без повторного обсуждения.

Контекст: `../CONTEXT.md` (решения пп.1–10 обязательны). Требования:
`src/games/billiards/docs/requirements.md` §5, §6 (D10), §8, §9 (D12).

## Цель и объём

Ядро 8-ball — чистый TS в `src/games/billiards/`, без DOM. Удар превращается в
лог событий физики, лог — в новый статус партии чистой функцией правил.
«Готово» — сквозная партия 8-ball целиком в тестах ядра через публичный `Game`.
UI не трогаем (кроме объявления хука ИИ заглушкой); постановка битка игроком,
экраны, ИИ-реализация, сеть — подфазы 02-b/c/d.

## Задачи

1. **Журнал удара — событие от физики.** `ShotLog` собирается как побочный
   продукт фиксированного шага: касания шар–шар (с выделением первого контакта
   битка), касания шар–борт (флаг «после первого контакта»), забития по порядку,
   скрач битка, вылеты со стола. Порядок событий стабильный, `Math.random`/время
   в шаг и лог не проникают.
   Файлы: новый `src/games/billiards/shot-log.ts` (или рядом с симуляцией),
   интеграция в шаг (`game.ts`: `advance`/`startShot`).
   Зависимости: нет. **Тесты: да.**
   *Done:* двойной прогон одного удара из одного состояния даёт побайтово равный
   лог; в логе различимы «первый контакт свой/чужой/8/нет» и «борт после
   контакта был/не было».

2. **Чистый разбор удара — правила 8-ball.** Чистая функция
   `resolveShot(stateBefore, log, settings) → stateAfter`: разбитие открытое
   (фол «без борта» не применяется, первый контакт любой); группы назначаются
   первым легально забитым после разбития; забил свой легально — ходит снова,
   иначе смена; фолы (скрач, неверный первый контакт, «без борта» вне разбития,
   шар со стола) → смена + флаг «биток с руки»; забитые при фоле остаются;
   8 на разбитии — переставка, не победа; неправильная 8: простые — фол +
   продолжение, турнирные — поражение (**требование** CONTEXT п.3).
   Функция не читает траекторию и не пишет служебных флагов в шары.
   Файлы: новый `src/games/billiards/rules-8ball.ts` поверх `modes/types.ts` +
   `base8ball.ts`, тесты рядом. Зависимости: 1 (форма лога).
   **Тесты: да.**
   *Done:* параметризованный набор «лог → исход» (открытый стол, группы,
   продолжение/смена, каждый вид фола, простые vs турнирные на неправильной 8)
   проходит целиком.

3. **Расширение состояния под 8-ball.** Новые поля при сохранении формы
   (`mode`, `version: 2` — **требование** совместимости): группы игроков,
   настройка `rules: simple|tournament`, статус партии (открытый/назначены/
   финиш + победитель/причина), флаг «биток с руки», счётчик `shotSeq`.
   Десериализатор принимает старые записи `version: 2` без новых полей
   (дефолты: стол открыт, `rules: simple`); чужие `mode` отвергает как раньше.
   Файлы: `src/games/billiards/state.ts`, `state.test.ts`.
   Зависимости: нет (параллельно с 1–2). **Тесты: да.**
   *Done:* round-trip сохраняет новые поля; старая запись без них загружается
   с дефолтами без ошибок.

4. **Переставка шаров.** 8 на разбитии → ножное пятно, занято — ближайшее
   свободное место по линии к центру (**требование** CONTEXT п.7); биток с руки
   после фола → начальная позиция или рядом, если занята, без пересечений
   с шарами (**требование** CONTEXT п.6; движимость битка игроком — 02-b, здесь
   только стартовая постановка в ядре).
   Файлы: helper переставки (`state.ts` / `rules-8ball.ts`), использование
   в resolve. Зависимости: 2, 3. **Тесты: да.**
   *Done:* разбитие с забитой 8 → «8 на пятне/точке у линии, стол открыт, ход
   у разбивавшего»; фол → биток на начальной/сдвинутой позиции без пересечений
   + флаг руки.

5. **Интеграция удара в очередь Game + контракт агентства.** `applyMove`:
   парсинг удара (`parseShot`) → симуляция до покоя с логом (1) → `resolveShot`
   (2) → новое состояние. Очередь на N игроков: продолжение хода (режим говорит
   «игрок не меняется») vs смена; `finished` из статуса партии. Объявить
   `chooseShot(видимое состояние) → удар` отдельно от применения (**требование**
   CONTEXT пп.9–10); в этой подфазе хук возвращает `null` (как сейчас
   `chooseMove`, `game.ts:260`).
   Файлы: `game.ts` (`applyMove`, очередь `turn`/`order`), `modes/types.ts`
   (сигнатура `chooseShot`). Зависимости: 2, 3. **Тесты: да.**
   *Done:* сквозная партия 8-ball в тестах через публичный `Game` (create →
   удары → финиш с победителем) без UI; тесты очереди обновлены под «забил
   свой — ходит снова, фол — смена + рука».

6. **Хэш состояния + `shotSeq` для будущей сети.** Детерминированный хэш
   (без наведения; спин — часть состояния по §5), инкремент `shotSeq` на каждый
   применённый удар — задел под 02-d (shooter-authoritative + hash/seq, §8).
   Файлы: `state.ts` (hash helper), `game.ts` (инкремент). Зависимости: 3, 5.
   **Тесты: да.**
   *Done:* один удар из одного состояния — равный хэш на двух прогонах; разные
   исходы — разный хэш; `shotSeq` строго растёт.

## Подфазы 02-b/c/d (списком, планы позже)

- **02-b «Экраны + локальная игра»** — `getSetupForm`: выбор режима →
  настройки (`rules`, имена) → кнопки старта; движимый биток с руки;
  панели/шкалы забитых; экран результата (`dialogs.show` + rematch/exit,
  паттерн tic-tac). Требует 02-a.
- **02-c «ИИ»** — `chooseShot` по §8: шкала + авто (не чаще раза в 2 партии,
  вниз быстрее), заморозка, ошибка ∝ трудности, `σ_min > 0`, без safety;
  персистентность шкалы (хотя бы интерфейс). Требует 02-a (хук).
- **02-d «Сеть»** — непрозрачный payload + hash/shotSeq поверх `Transport`;
  параметры режима партнёру при старте, хост — правда; resync. Требует 02-a
  (форма состояния).

## Забыто

- Пары шаров и события лога — стабильный порядок (§5); seed — часть состояния.
- `version: 2` не ломается: новые поля опциональны при чтении, дефолты рядом
  с валидатором.
- Call-pocket нет (выключен по умолчанию, §6); «3 фола подряд» не берём.
- Разбитие открытое; группы — первым легально забитым после разбития; забил
  свой — ходит снова.
- Геометрию/физику канона 01-a/01-c не трогаем.
- `BilliardsUi` (прицел/сила/shoot) не меняется в этой подфазе.
- Настройки этой фазы: только `rules` + имена; экран выбора режима — через
  `getSetupForm` (02-b), отдельного экрана платформы не строим (D1).

## Риски

- Журнал вносит недетерминизм (порядок, float) — ловят задачи 1 (двойной
  прогон) и 6 (хэш).
- Тесты `game.test.ts` очереди поедут — задача 5 явно включает их обновление.
- Соблазн служебных флагов в состоянии — ревью: resolve читает только
  `stateBefore + log + settings`.
- Соблазн ИИ/сети «заодно» — отсекается: хук `null`, хэш/seq без протокола.
- `resolveShot` в god-функцию — разбор по фолам/8/группам отдельными чистыми
  помощниками.

## Решения

- Внешних библиотек нет: журнал и разбор — доменная логика под замороженную
  физику. Цена: только время.
- `result/rematch` из `tic-tac/game.ts:233` — образец для 02-b. Цена: 0.
- Форма партнёру при старте сети — весь режим-конфиг (`mode + rules`, имена),
  правда — хост (**требование** CONTEXT п.4; реализуется в 02-d).
