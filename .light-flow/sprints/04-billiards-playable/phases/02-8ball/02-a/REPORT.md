# REPORT — Подфаза 02-a «Ядро правил 8-ball»

## Что сделано

Партия 8-ball в ядре: удар превращается в журнал событий физики, журнал —
чистым разбором правил в новое состояние. UI, сеть и сохранение не менялись
(кроме заглушки хука ИИ и обновления тестов под новое состояние).

- **Журнал удара** (`shot-log.ts`): `ShotLog` — первый контакт битка
  (`firstContactId`), флаг «борт после первого контакта», забитые по порядку,
  скрач битка, вылеты со стола. Собирается как побочный продукт шага без
  `Math.random`/времени; `physics.ts` получил опциональные хуки событий и
  `simulateToRestWithLog`/`applyShotWithLog` (старые функции не изменились —
  поведение физики без журнала то же).
- **Правила 8-ball** (`rules-8ball.ts`): чистая `resolveShot(before, log,
  settings)`. Разбитие открытое (фолы «первый контакт»/«без борта» не
  применяются); группы назначаются первым легально забитым после разбития;
  забил свой — ходит снова, иначе смена; фолы (скрач, неверный первый контакт,
  «без борта» вне разбития, шар со стола) → смена + биток с руки; забитые при
  фоле остаются; 8 на разбитии — переставка, не победа; неправильная 8 —
  простые: фол + продолжение, турнирные: поражение; легальная 8 после зачистки —
  победа.
- **Состояние** (`state.ts`): новые поля (`groups`, `rules`, `phase`, `winner`,
  `finishReason`, `ballInHand`, `shotSeq`) при сохранении формы `mode`,
  `version: 2`. Старые записи без новых полей читаются с задокументированными
  дефолтами; битые поля отвергаются; чужие `mode` и `version: 1` — как раньше.
- **Переставка** (`rules-8ball.ts`): 8 после разбития → ножное пятно, занято —
  ближайшая свободная точка по линии к центру (далее — в обратную сторону);
  биток с руки после фола → головное пятно, занято — ближайшая свободная точка
  кольцами; пересечения исключены; допуск — диаметр из конфига режима.
- **Интеграция** (`game.ts`): `applyMove` → `applyShotWithLog` → `resolveShot`;
  очередь читает `turn`, который ведёт разбор; хук `chooseShot` объявлен
  отдельно от применения и пока возвращает `null` (02-c).
- **Хэш** (`state.ts`): `hashBilliardsState` — детерминированный FNV-1a по
  канонической строке (шары по id, группы по ключам сортированы), задел под сеть.

## Отклонения

- **`shotSeq` инкрементируется в `resolveShot`, а не в `game.ts`** (план
  называл `game.ts`). Причина: разбор — единственное место, где известен факт
  применённого удара, включая отказ по `finished`. Факт выполнения условия
  («счётчик строго растёт») не меняется.
- **Итог `finished` показывает `#showResult()`**: конец партии сразу уходит
  в диалог результата (существующий механизм игры), экран результата как
  отдельный вид — 02-b.
- **8 на разбитии**: возвращается на стол переставкой (снято допущение
  задачи 2), стол остаётся открытым, ход у разбивавшего.
- **Неправильная 8 в простых правилах**: фол + продолжение, 8 остаётся забитой
  (потеряна), биток с руки.
- **`offTableIds`** на практике всегда пуст: физика не выпускает шары за борт;
  поле зарезервировано под правила (`rules-8ball.ts:111`).
- **Движимость битка игроком** после фола — не здесь (`withPlacedCue` уже умеет
  ставить в любую точку стола и расталкивать шары), UI-постановка — 02-b.
