# REPORT — Подфаза 02-b «Экраны + локальная игра»

## Что сделано

Локальная партия 8-ball играется за одним экраном: экран настроек двумя
шагами, цикл хода с плашкой перехода, движимый биток после фола, шкалы
забитых по игрокам, экран результата, реактивные инсеты панелей.

- **Форма преднастройки двумя шагами** (`game.ts:setupForm`): «Шаг 1. Режим»
  (select `mode`), «Шаг 2. Параметры и запуск» (select `rules` простые/турнирные
  + кнопки «Двое за экраном», «С компьютером», «Создать сетевую партию»,
  «Присоединиться»). Схема статична и создаётся один раз (`src/main.ts:87`),
  поэтому шаги — схлопывающиеся группы одной формы, платформа не расширена.
  Кнопки старта задают состав: `defaultPlayers({humans:2})`,
  `defaultPlayers({humans:1, computers:1})`, `lobby.showHost()/showClient()`.
  Имена игроков игра собирает сама; выбранные правила идут в состояние партии.
- **Передача хода** (`rules-8ball.ts` + `state.ts` + `game.ts`): разбор лога
  определяет следующие условия — кто ходит (`turn`), причина (`turnReason`:
  `break`/`foul`/`pottedOwn`/`pottedOther`) и права подготовки (`prep`:
  `canPlaceCue`, `canChooseCueBall` — у 8-ball всегда `false`). Всё сериализуется,
  чтобы сеть (02-d) и сохранение (08) воспроизвели начало хода.
- **Фазы хода** (`TurnPhase`: `preparing`/`animating`/`passing`) в игре,
  несериализуемы. Между ударами поле не трогается: после скраша биток **не
  ставится разбором**, появляется на подготовке следующего хода
  (`needsCuePlacement()`/`#effectivePlacement()` с `cueBallInHandPosition`).
  `applyMove` отдаёт `getTurnHandoff()`, UI показывает плашку и по её
  исчезновению зовёт `acknowledgeTurn()`.
- **Плашка перехода хода** (`BilliardsUi.vue`): по центру стола, `pointer-events:
  none`, текст «Ход: <игрок> — <причина>»; при продолжении хода — «забил свой —
  продолжает». Показывается после конца реплея, исчезает сама (1.4 с), ввод
  заблокирован на это время.
- **Движимый биток**: право позиционировать = фаза подготовки ∧ `prep/
  ballInHand`; границы стола и мягкое выталкивание пересечений — существующие
  `withPlacedCue`/`#placementMax`. Позиция уходит в удар (`cueX/cueY`).
- **Панель игроков**: `getPocketedByPlayer(playerId)` раскладывает забитые по
  назначенным группам (`state.groups`); биток и 8 никому не приписываются; при
  открытом столе забитые показываются у игрока, чей ход (допущение зафиксировано
  в коде). Виджет бонусов из панели 8-ball убран.
- **Экран результата**: имя победителя и причина («забил 8» / «неправильно забил
  8»); кнопки «Ещё раз»/«В меню» как у tic-tac.
- **Настройки**: `serializeSettings`/`applySettings` для `rules`, мусор
  игнорируется.
- **Дефект реек/инсетов** (исполнителем): инсеты зон стали наблюдаемыми в слоте
  (`src/ui/ui-zones/slot.ts`: `insets` + `setInsets` с сравнением значений),
  `LayerGameUi` пишет через слот, `BilliardsUi` пересчитывает полосу реек по
  подписке. Публичный контракт `UiZones.insets` не изменён; тест
  `src/ui/ui-zones/slot.test.ts`.

## Отклонения

- **`game.test.ts` пересобран после потери файла.** Правка через PowerShell
  испортила кодировку строки, а последующий `git checkout` откатил файл к
  версии фазы 01 — вместе с тестами 02-a. Тесты восстановлены заново по
  условиям планов 02-a/02-b (сценарии удара строятся явно, а не «как пирамида
  разобьётся»): партия, забил свой, скраш с передачей хода, финиш с `winnerId`,
  очередь N игроков, `chooseShot`, забитые по игрокам, постановка битка, формы и
  запуски. Прежних имён тестов может не быть — покрытие восстановлено по
  планам, не побайтно.
- **Шаги настройки — схлопывающиеся группы одной формы**, а не отдельный
  модальный шаг: схема статична (`core/form/controller.ts:17`), пересборка схемы
  платформой потребовала бы её расширения.
- **Причина перехода хранится в состоянии** (`turnReason`), плашка читает её;
  не из рантайма — чтобы сеть/сохранение воспроизвели начало хода.
- **Самовосстановление фазы:** если игра осталась в `passing` без передачи
  (например, партия без UI), `BilliardsUi` сам зовёт `acknowledgeTurn()` — иначе
  стол нельзя целить.

## Прицел: скачки предсказания при срезках (решение 2026-10-17)

- Замер по углу с шагом 0.001 рад: первый шар удара меняется в тонких срезках,
  когда линия проходит между двумя шарами почти одинаково. Направление цели
  скачет, это поведение физики.
- Точка касания в предсказании теперь на касании по нормали (`physics.ts`,
  `resolvePairs`), гост не проваливается в шар.
- Решение пользователя: оставить поведение физики без сглаживания отрисовки.

## Исправление: последний свой шар давал фол

- **Симптом (живьём):** забитие последнего своего шара переводило ход сопернику
  с причиной «фол».
- **Причина:** `game.applyMove` передаёт в `resolveShot` состояние после удара
  (`rest`), где забитые шары уже неактивны. `classifyShot` видел группу
  зачищенной до удара и требовал контакт с 8 → фол. Тот же дефект ломал победу
  «8 вместе с последним своим шаром».
- **Правка:** `resolveShot` восстанавливает активность шаров, погашенных этим
  ударом, перед классификацией (`rules-8ball.ts`, `shotStart`). Результат
  `balls` не меняется.
- **Тесты:** `rules-8ball.test.ts` — «последний свой шар, забитый ударом»,
  «последний свой шар вместе с 8 — победа». Прогон 523/523.
- **Воспроизведение:** перебор углов и сил через физику (один свой шар, id 1):
  до правки все 6 ударов, которыми он падал, давали фол. После правки перебор не
  повторён (временный скрипт удалён) — нужна живая проверка.
