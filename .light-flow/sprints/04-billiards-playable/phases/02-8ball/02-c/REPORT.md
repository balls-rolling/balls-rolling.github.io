# REPORT — Подфаза 02-c «ИИ-противник»

## Что сделано

- **Оценка удара** (`src/games/billiards/ai.ts`): перебор своих шаров × лузы через
  ghost-ball, отсев перекрытий пути (аналитически, без симуляции), метрика
  трудности (срезка + дистанции), выбор лучшего **легального** удара (цель по
  правилам: разбитие → вершина, свои/8 после зачистки, открытый стол → групповые).
  Детерминированный порядок (ничьи — по id).
- **Ошибка по навыку**: гауссов шум (Бокс–Мюллер) от seeded PRNG `mulberry32`;
  seed из `state.seed` и `state.shotSeq`; `σ_min > 0` (0.004 рад). `Math.random` и
  время не используются.
- **Шкала сложности** (`src/games/billiards/difficulty.ts` + `game.ts`): одна
  шкала 0..4, режим `"auto" | number`; «авто» двигается между партиями (не чаще
  раза в 2 партии, вниз быстрее вверх, dead-zone на чередование); внутри партии
  заморожена (`#frozenScale`). Обновление — по исходу партии (`#onFinished`),
  только когда в партии был компьютер.
- **Преднастройка и сериализация**: select `difficulty` в `SETUP_8BALL`;
  `serializeSettings`/`applySettings` несут `difficulty` и `scale`, мусор
  игнорируется.
- **Ход компьютера через цикл хода** (`game.ts` + `BilliardsUi.vue`): `chooseMove`
  всегда `null` — `Session` удар мгновенно не применяет; UI сам берёт план
  (`planComputerTurn`), показывает прицеливание и бьёт тем же путём, что человек
  (`beginShot` → `startShot` → реплей → `makeMove` → плашка → `acknowledgeTurn`).
  Серия ходов ИИ продолжается сама. Ввод человека на ходе компьютера заблокирован.
- **Видимое прицеливание** (требование пользователя): перебор кандидатов по
  160 мс, финальный прицел на выбранном, пауза 800 мс, удар; те же контроллы
  прицела и силы, что у человека. Итого около 1.4 с.
- **Скрач**: при `ballInHand` ИИ ставит биток (`cueX/cueY`), точка без пересечений
  и в бортах.

## Отклонения

- **Знак ghost-ball в плане был неверен.** Формула `ghost = obj − 2r·(obj−pocket)/‖…‖`
  ставит гость с неправильной стороны. Реализовано физически верное направление
  (`ghost = target − 2r·(target→pocket)`).
- **Разбитие — отдельный кандидат** (прямой удар по вершине, сила 0.95): пирамида
  закрыта, иначе `chooseShot` на разбитии давал `null` и ход залипал.
- **Запасной «плохой, но легальный» удар** (`directHitCandidate`), когда забить
  нечем. Согласуется с CONTEXT п.9 (safety play не делаем).
- **`PropertySpec` не заводился:** сложность — настройка игры, а не свойство
  игрока; сделан select в `SETUP_8BALL` (образец tic-tac).
- **`Session` не тронут** — вариант (а): `chooseMove` → `null`.
- **`serializeSettings` теперь 3 поля** — существующий тест переведён на
  `toMatchObject` (покрытие не потеряно).
- **`getDifficulty()`** добавлен как публичный метод (тесты/UI), в проде не
  используется — сверх плана.

## Замечания пользователя (2026-10-17)

- **Сила удара на игрока — сделано.** `BilliardsUi.vue`: `powerByPlayer` (рантайм),
  `syncPowerToPlayer()` при смене хода (в подписке на сессию, в `endTurnNotice`, на
  монтировании), запоминание — в `sendPowerPreview` только на ходе человека (силу
  ИИ не сохраняем). Финты получат ту же механику, когда появятся (фаза 07).
- **«Избыточная подкрутка» — измерено, это не спин.** Прогон удара в борт с
  записью бокового вращения: `wz = 0` на всём пути, путь — прямые отрезки. Видимое
  — **незеркальный отскок от подушки**: трение подушки (`TANG_KEEP_RAIL = 0.78`,
  `constants.ts:105`) гасит касательную скорость, поэтому отскок доворачивается к
  нормали (замер: приход 45° → отскок ~30° к горизонтали). Спин появляется только
  при срезке шаром (`MU_BALL = 0.05`, в диапазоне Dr. Dave 0.03–0.08).
  **Решение пользователя 2026-10-17: оставить как есть** (физически верно,
  `TANG_KEEP_RAIL` не трогаем).

## Правки по итогам lf-verify (2026-10-17)

Проверка аналитиком выявила три крупных замечания; исправлены так:

1. **Тест хода компьютера через фазы — добавлен.** `game.test.ts`: «ход
   компьютера проходит цикл фаз без залипания passing» (подготовка → план →
   `startShot` → `advance` до покоя → `applyMove` → `passing` → `acknowledgeTurn`
   → `preparing`) и «возобновлённая партия: план компьютера доступен без кадра
   отрисовки». Также добавлен тест «не бьёт 8, пока есть свои шары группы»
   (`ai.test.ts`).
2. **Залипание при возобновлении на ходе компьютера — исправлено.** Причина:
   `planComputerTurn` читал `#lastState`, а тот выставлялся только в `draw()`
   (кадром позже). Теперь `createInitialState` и `deserializeState` сразу
   выставляют `#lastState`, сбрасывают `#lastFinished` и ставят фазу `preparing`.
   Покрыто тестом (см. п. 1).
3. **Связанность «ход ИИ = UI» — решение принято.** Оставляем вариант (а):
   `chooseMove` → `null`, ход компьютера ведёт UI игры тем же циклом, что
   человека. Это соответствует CONTEXT пп.9–10 (хук выбора отделён от применения)
   и не нарушает «ядро без UI» для логики ИИ (`ai.ts`/`difficulty.ts` — чистый TS).
   Ограничение: без UI (демо/headless) компьютер не играет. Бильярд сейчас не
   объявляет `getDemoPlayers`, поэтому платформа его в демо не берёт — стопора нет.
   Если в фазе 08 понадобится фоновое демо бильярда, оркестрацию хода надо будет
   перенести в ядро — это долг «игрового тика» (D12). Запись в BACKLOG.

Мелкое, исправлено:
- Дублирование правил цели убрано: `legalTargets` вынесена в `aim.ts` (единственный
  источник), `ai.ts` импортирует её.
- Уточнена формулировка «тест фаз» в отчёте.

Мелкое, оставлено с записью (вне объёма 02-c, в BACKLOG):
- `#names`/`#agents` не заполняются при возобновлении партии (заполняются только
  при старте) — на восстановленной партии плашка покажет id вместо имени, а
  авто-шкала не обновится по её исходу. Существующий долг 02-b/12-b.
- Лишние публичные API (`getDifficulty`, `candidateShots`, `mulberry32`) —

## Открыто

- **Живьём не проверено пользователем:** видимое прицеливание, ход ИИ с реплеем,
  постановка битка ИИ после фола. Исполнитель проверил по DOM/ARIA на dev-сервере
  (плашка, `aria-valuenow`, `disabled`), но скриншот снять не удалось.
- **Сохранённая сложность не подставляется в контролл формы** — схема статична
  (то же ограничение, что у tic-tac).
- **Метр силы после хода ИИ остаётся на его значении** — общий контролл.
- **Разбитие ИИ всегда прямое по центру вершины**, попытки забить нет.
- **Seed партии — существующий `DEFAULT_SEED = 1`**, игра его не рандомизирует;
  шум ключуется `seed + shotSeq`.
- **Safety play, спин/точка удара, рейтинг `game/<id>`** — отложены по плану.
- **Prettier не запускался** — чтобы не смешивать форматирование с правками.
- **Не закоммичено** — всё в рабочей копии.
