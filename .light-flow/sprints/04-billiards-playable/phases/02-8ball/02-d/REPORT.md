# REPORT — Подфаза 02-d «Сетевая игра»

## Что сделано

- **Непрозрачный payload удара** (`core/net/protocol.ts`): `move` несёт
  `{t:"move", m: Move, seq?, hash?}`; диспетчер состав удара не разбирает, мусор
  отбрасывается молча. `NetApi.remoteMove(move, meta)`; `link.sendMove(move, meta)`.
  Крестики-нолики не менялись: их `Move = {x,y}` идёт внутри `m`, входящий
  применяется фолбэком. `PROTOCOL_VERSION` поднят 1 → 2 (формат изменён
  несовместимо).
- **Сетевой мост бильярда** (`ui/games/billiards/net.ts`, новый модуль без Vue):
  подключение к сети, роли хост/гость по `transport`, `outgoingState`/
  `outgoingSettings` только у хоста. Входящий удар играется реплеем тем же циклом,
  что ход человека (`playShot` → `startShot` → `advance` → `makeMove` → плашка →
  `acknowledgeTurn`), а не применяется мгновенно. Для этого `NetLink` получил хуки
  игры (`setGameHooks`/`setOutgoingState`/`setOutgoingSettings`/`requestResync`) с
  фолбэком на `session.makeMove` для других игр.
- **hash + shotSeq, shooter-authoritative, идемпотентность**: после применения
  (состояние из `session.save()`, не из реплея) отправитель прикладывает
  `seq = shotSeq` и `hash = hashBilliardsState`; приёмник сверяет хеш.
  `shotId = (seed, seq, shooterId)`, `lastAppliedSeq` на отправителя; дубликат или
  устаревший `seq` — no-op; смена seed сбрасывает счётчики.
- **Ресинк**: расхождение хеша → гость шлёт `resync`, хост отвечает `sync`; у хоста
  расхождение — он сам шлёт снимок. После `adoptState` — `resetRuntime()` и возврат
  состояния игре (`deserializeState`), иначе `startShot`/прицел без базы до кадра.
  Сообщение `resync`, `NetApi.requestResync`.
- **Параметры партнёру при старте**: `mode/rules/seed/order` — в снимке
  `session.save()`; настройки (`rules/difficulty/scale`) — в `sync.settings`, гость
  применяет через `applySettings`. Порядок игроков совпадает (хост первым).
- **Смена хода с удалённым**: гейт ввода — «текущий игрок — мой локальный человек»
  (предикат `currentPlayerIsLocalHuman`, по `agent` и `transport`). На ходе
  удалённого ввод закрыт, компьютерный путь не стартует; после удалённого удара —
  реплей, плашка, `acknowledgeTurn`, разблокировка; возврат хода тому же игроку не
  залипает (очередь из `turnReason`/`nextPlayer`).

## Отклонения

- **`PROTOCOL_VERSION` 1 → 2** (в плане не было): формат `move` изменён
  несовместимо, версия для этого и существует.
- **`parseShot` экспортирован** из `game.ts` — нужен мосту, чтобы не дублировать
  разбор удара.
- **Хост при расхождении шлёт снимок сам** (`sendState`), гость просит `resync` —
  следствие «хост — источник правды»; план описывал только гостевой путь.
- **Настройки в `sync`** — по задаче 5; в сетевой партии ИИ нет, но применены.
- **Гейт ввода объединён** в один предикат `currentPlayerIsLocalHuman` (агент +
  транспорт), заменив прежние проверки по `computerTurn`.

## Открыто

- **Живой WebRTC не проверен** (0 ICE) — только парные фейк-транспорты.
- **Живой сетевой UI в браузере не проверен:** визуальный реплей входящего удара,
  разблокировка после плашки, ресинк в DOM/ARIA — покрыты node-тестами, не живьём.
- **Буфер неупорядоченных ударов** не реализован (отложено планом): при разрыве
  `seq` ход применяется без буфера, полагаемся на упорядоченность WebRTC.
- **Кросс-платформенный хеш** — по сырым float (риск плана); в рамках одной
  платформы детерминирован.
- **Контрольная сумма `Invite`, игровой реванш, кросс-платформенный квантованный
  хеш** — отложены планом.
- **Prettier не запускался** — чтобы не смешивать форматирование с правками.
- **Не закоммичено** — всё в рабочей копии.
