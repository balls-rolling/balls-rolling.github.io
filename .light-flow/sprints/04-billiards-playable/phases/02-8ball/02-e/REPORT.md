# REPORT — Подфаза 02-e «Живой прицел и синхронный удар»

## Что сделано

- **Живые сообщения** (`core/net/protocol.ts`, `ui/net/link.ts`): `prep {t,p}` и
  `shot {t,m,seq}`; платформа состав не разбирает, мусор отбрасывается молча.
  `PROTOCOL_VERSION` не поднимался — расширение аддитивно, неизвестный `t`
  игнорируется (совместимость с 02-d-клиентом). `NetLink`: `sendPrep`, `sendShot`,
  хуки `onRemotePrep`/`onRemoteShot`.
- **Троттлинг потока подготовки** (`ui/games/billiards/prep-stream.ts`, новый):
  коалессер «последнее значение», без Vue, с инжектируемыми часами (первое — сразу,
  хвост — по таймеру ~33 мс). Подключён из всех точек ввода: угол (перетаскивание,
  шкала, сбросы), сила (сила/колесо/шаги/клавиши), позиция битка. Гейт: только
  подготовка, только локальный ход; молчит на реплее, плашке, чужом ходе, финале и
  без сети; возобновляется после `acknowledgeTurn`.
- **Приём чужого прицела**: (первая версия — отдельный слот `#ghost` с упрощённой
  отрисовкой; **заменена рефактором ниже** на модель «участник с источником ввода»:
  чужой прицел живёт в участнике соперника и рисуется тем же путём, что свой).
- **Синхронный старт удара**: бьющий в сетевой партии шлёт `shot` до первого кадра
  реплея (`seq = state.shotSeq + 1` до применения); приёмник по `shot` стартует свой
  реплей тем же путём (`playShot`), но не применяет; дубликат/старый `seq` реплей не
  перезапускает.
- **Ожидание авторитетного результата**: приёмник после своего реплея держится;
  применение — по приходу `move` с тем же `seq`, сверка хеша как в 02-d; затем ход
  переключается у обоих. Фолбэк на 02-d-путь, если парного `shot` не было.
  Идемпотентность по `seq`/`shotId` сохранена.
- **Таймаут 5+5 с**: нет результата 5 с → плашка «Завершение хода другого игрока» +
  `requestResync()`; ещё 5 с → новый узкий метод `NetLink.signalPeerUnresponsive()`
  (выставляет `peerLeft`) → существующий диалог обрыва (`NetRecovery`/`NetDropDialog`
  не менялись). Таймеры снимаются на результате, смене хода, финале и `detach`.

## Отклонения

- **Сигнал `shot` отправляется после успешного `startShot`, а не строго до него**
  (поправлено мной после проверки): реплей шагает по кадрам, поэтому «до реплея»
  сохраняется, но при отказе `startShot` приёмник больше не ждёт напрасно 5+5, и
  поток подготовки не остаётся заглушённым.
- **Гейт потока — на push-времени** (`prepGateOpen`) плюс `setEnabled` на старте
  удара/смене хода, а не вызовы из каждой точки ввода: эффект тот же, меньше связности.
- **Мост получил инжектируемые часы** (`clock`/`waitMs`) и колбэки `applyIncoming`/
  `onWaiting` — нужны для тестов таймаута без реального ожидания.
- **Отрисовка ghost упрощённая:** пунктир от битка в чужом угле и метка битка, без
  физического предпросмотра; `power` кадра хранится, но в рендере не используется.

## Рефактор к модели «участник с источником ввода» (2026-10-18)

Замечание пользователя: второй игрок видел упрощённую «фигню» (пунктир и метка
битка) вместо полноценного предпросмотра, и сила соперника не показывалась.
Причина — мой ghost-костыль: отдельный слот с упрощённой отрисовкой вместо общей
модели. Решение пользователя: для игры нет разницы между локальным, ИИ и сетевым
участником; разница только в источнике данных.

Что сделано:
- **Участники в игре** (`game.ts`): `setRoster(players)` — состав из сессии (имена,
  агенты, транспорт; чинит `resume`). На участнике живут `aim`, `power`, `cue` и
  восстанавливаются на его ходу. Публичные: `currentParticipant`,
  `getParticipant*`/`setParticipant*`, `isCurrentLocal`, `commitShot(playerId)`.
  `#aim`/`#previewPower`/`#cuePlacement` заменены на поля участника.
- **Источники ввода**: локальный (UI), сетевой (`prep`/`shot` из моста), ИИ
  (`planComputerTurn`) пишут в своего участника и просят удар через `commitShot`.
- **Одна отрисовка для всех** (`render.ts`): `drawGhostAim` и слот ghost удалены.
  Прицел текущего участника рисуется тем же путём (линия, гость, физический
  предпросмотр, полный шар битка). Цвет — параметр вида `aimPale`: локальный
  участник — белый, не локальный (сеть/ИИ) — бледно-оранжевый.
- **UI — адаптер**: `syncRoster`, ввод через `setParticipant*`, блокировка по
  `!isCurrentLocal()`, сила текущего участника на контролле (в т.ч. соперника —
  заблокированном). Память силы на игрока (`powerByPlayer`) убрана — теперь в участнике.

Отклонения рефактора:
- **`isCurrentLocal()` = `agent === "human" && transport === "local"`**, а не просто
  `transport === "local"`: у ИИ транспорт тоже `local`, иначе его ход не блокировал бы
  ввод и рисовался бы белым — против цели.
- Участник хранит и `cue` (позиция битка) — нужно для видимости постановки битка
  соперника; мост пишет `cue` из `prep`.
- Тяжёлому интеграционному тесту добавлен явный `timeout: 20000` (под нагрузкой
  всего сьюта упирался в дефолт 5 с; логика не менялась).

Проверки после рефактора: `typecheck` 0, `test` 586/586, `build` 0.

## Правки по замечаниям (2026-10-18, после живой проверки)

- **Позиция битка соперника не отображалась.** Причина: мост писал её через
  `setCuePlacement`, а тот закрыт локальным гейтом `canPlaceCue()` — при чужом ходе
  запись молча отбрасывалась, и предсказание рисовалось из старой позиции битка.
  Добавлен `setParticipantCue(id, x, y)` без гейта (данные соперника проверены на
  его стороне); мост пишет им. Показ идёт через `#effectivePlacement`, как раньше.
- **Угол не переносится между ходами.** В начале хода он выставляется по правилам
  (на целевой шар). `acknowledgeTurn` теперь сбрасывает прицел текущего участника;
  сила по-прежнему своя у каждого участника и сохраняется.
- **Позиция битка соперника появлялась только после сторонней перерисовки**
  (ресайз окна). Причина: основной холст рисуется по требованию, а `prep` меняет
  вид вне сессии — перерисовка не запрашивалась. Мост получил зависимость
  `requestDraw`, вызывается после применения кадра подготовки.
- Тесты: `game.test.ts` — «позиция битка соперника принимается без локального
  гейта», «угол не переносится между ходами». Прогон 588/588.
