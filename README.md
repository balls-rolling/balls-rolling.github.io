# Платформа мини-игр

Веб-платформа для запуска мини-игр: ядро с базовыми классами, глобальный синглтон
платформы и «сессия» — экземпляр запущенной игры. Игры — наследники базовой игры.

Сайт: **https://balls-rolling.github.io/**

## Что уже есть

- **Каркас платформы** — реестр игр, сессии, нативные `<dialog>` и `<details>`,
  темы (OKLCH, системный акцент), уведомления, настройки с автосохранением,
  сохранение и восстановление партии, лобби и сеть поверх WebRTC без сигналинг-сервера.
- **Крестики-нолики** на бесконечном поле — против компьютера, хот-сит и по сети.
- **Бильярд (вид строго сверху)** — 8-ball: правила, экраны преднастройки,
  локальная партия, ИИ-противник с настраиваемой сложностью, сетевая игра с живым
  прицелом соперника и синхронным ударом.

## Стек

Vue 3 + TypeScript + Vite. Минимальный toolchain: `vite`, `vue-tsc`, `prettier`,
`vitest`. Внешние библиотеки: только `@lucide/vue` (иконки) и `qrcode.vue` (QR).

Требуется Node `^22.18.0 || >=24.12.0`.

## Быстрый старт

```bash
npm ci          # установка зависимостей
npm run dev     # локальный сервер разработки
npm run build   # сборка в dist/
npm run preview # предпросмотр собранной версии
npm run typecheck
npm test
npm run format
```

## Структура

```
src/
  core/          ядро платформы: игра, сессия, игрок, сеть, формы, зоны UI, сохранения
  games/         ядра игр (без DOM): крестики-нолики, бильярд (правила, физика, ИИ)
  ui/            слой интерфейса: экраны, диалоги, лобби, сеть, игры
  styles/        токены и базовые стили
lab/             эксперименты с отрисовкой (не часть приложения)
reference/       референсы для оформления стола
```

Ядро игры не зависит от UI: UI — слой-адаптер, который вызывает методы ядра и
показывает результат. Поэтому демо, сеть, хот-сит и тесты — просто разные
потребители одного ядра.

## Деплой

Статика собирается в `dist/` и публикуется на GitHub Pages workflow-ом
`.github/workflows/deploy.yml` при пуше в `main` (Pages → Source: GitHub Actions).
Сайт живёт в корне домена `balls-rolling.github.io`, поэтому `base` в конфиге Vite
не задаётся.

WebRTC требует HTTPS — GitHub Pages даёт его автоматически. Ссылки-приглашения
передаются query-параметрами, поэтому SPA-роутинг-фолбэк не нужен.

## Процесс

Проект ведётся по методологии light-flow: фазы внутри спринтов, каждая проходит
обсуждение → план → исполнение → проверку. Документы процесса — в `.light-flow/`.
